One small calculation.

Address 3 starts with 41. Read it into A, then press Add one to A. A becomes 42. Address 3 still holds 41, and address 4 still holds 0: the calculation has changed the working copy inside the processor.

Press Write A to address 4 to save the result in memory. Now address 4 holds 42. A keeps its value too.

Predict it. Start again, read 41 into A, then change address 3 to 99 before adding. What will A become?

Show an explanation

A becomes 42. The addition uses the copy already in A. It does not read address 3 again.

Room for the result.

A is still only one byte. It can hold an unsigned value from 0 to 255, even when a calculation produces a larger answer.

Try it. Start again. Change the byte at address 3 to 255 before reading it. Then read, add one, and pause before writing. What is in A? What is still in memory?

Show an explanation

The full sum is 256, but A holds 0: the rightmost eight bits. Address 3 still holds 255, and address 4 still holds 0. The carry flag is now 1. Writing stores A’s 0 at address 4 and leaves carry at 1.

Try 255 + 1 ↑

This is the same wraparound we met in What happens after 255?. Here, a real processor instruction performs the addition.

A bit to remember.

The processor has small pieces of state called flags. The carry flag, named CY on the 8080, is one bit. This addition sets it to 1 when the sum does not fit in eight bits, and to 0 when it does.

CY is separate from A. It remembers the carry from the addition; it does not make A a nine-bit register. Writing A to memory writes just its eight bits. The load and store instructions leave CY alone.

Compare. Start again with 127 at address 3. Does 127 + 1 set carry?

Show an explanation

No. 128 fits in eight bits: A becomes binary 1000 0000, and CY is 0. Turning on the highest bit in A is different from carrying beyond the byte.

Try 127 + 1 ↑

Starting again restores the lesson’s chosen values, including CY = 0. Editing memory by itself never changes A or CY.

Load, calculate, store.

These three instructions form a small program: bring a value in, work on it, and put the result somewhere. Each button runs one instruction; the others wait their turn.
