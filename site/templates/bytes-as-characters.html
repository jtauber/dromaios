Bits and meaning · Characters

Bytes can
be letters.

We have used bytes as numbers. With an agreed code, those same bits can stand for letters, digits, and punctuation. Nothing in the byte itself says which meaning to choose.

A letter needs an agreement.

The starting bits are 01000001: decimal 65, or hexadecimal 41. Read as an unsigned number, they mean sixty-five. Read using ASCII, they stand for the uppercase letter A.

A character encoding supplies the agreement between a stored value and a character. ASCII is one such agreement. Its name stands for American Standard Code for Information Interchange.

Select A, then a. They are different characters with different values. Notice that the rightmost bit is not the one that changes.

Try it. Select A, then turn on the bit worth 32. Which character appears?

Show an explanation

Lowercase a. Its value is 65 + 32 = 97: binary 01100001, hexadecimal 61. That relationship is part of ASCII’s arrangement, not a rule for every byte or every encoding.

The character 0 is not a zero byte.

Select the example labelled 0. Its decimal value is 48, with bits 00110000. That is the code for the printed digit.

Now press Clear all bits. The byte becomes zero, and the character readout says NUL, meaning Null. It has no printed shape. The three letters NUL are our label for one code; they are not three letters stored in this byte.

The same distinction matters with more digits. The number 65 fits in one byte. The text “65” uses two ASCII characters: “6” followed by “5”.

Predict it. Select the character 0, then change the decimal value from 48 to 49. What appears?

Show an explanation

The character 1. ASCII’s ten digit characters occupy consecutive values, 48 through 57. A program must interpret those character codes if it wants to calculate with the number they spell.

Some codes leave no printed mark.

Select Space. Its value is 32. A gap between words still needs a code, so a space occupies a byte just as a letter does. This view uses the label SP to make it visible.

Select Line feed. Its value is 10, labelled LF. It is a control code: a receiver can use it to move to another line rather than draw a character. This explorer only identifies the code; it does not move a cursor.

Try decimal 7 (BEL, Bell), 13 (CR, Carriage return), or 127 (DEL, Delete). These labels let you inspect codes that otherwise would be hard to see. Selecting them here does not ring a bell or delete anything.

ASCII uses seven bits.

A byte has 256 possible patterns, but ASCII assigns only values 0 through 127. We hold those values in eight bits with the leftmost bit set to zero.

Try it. Select A, then turn on the bit worth 128. Is it still an ASCII letter?

Show an explanation

No. The byte now holds 193: 11000001, or hexadecimal C1. It is a valid byte, but outside ASCII. The explorer keeps all eight bits and does not guess another encoding.

Other encodings provide more characters, sometimes using several bytes for one character. Sender and receiver need to agree on the encoding to read the same text.

A reference for the codes

The ASCII code table and names used here can be checked in RFC 20: ASCII format for Network Interchange. The letter shapes come from your browser’s font; the code specifies the character, not its exact drawing.

From a lamp pattern to a letter.

In Waiting for a byte, the 8080 received a byte and echoed it to the lamps. If that byte were 65, the lamps would show 01000001. A display using ASCII could show A for the very same output.

The CPU transfers the byte. The display gives it a visible form. The next lesson makes that connection with a simple text terminal.
