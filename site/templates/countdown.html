Three things left to do. Then two. Then one. This loop subtracts one each time and finishes when the result reaches zero.

One less each time.

The load puts our starting count, 3, into A. The next instruction is SUI 1: subtract one from A. It makes A = 2, and the store writes that result to address 4.

The subtraction also updates the zero flag, Z. Z = 1 means the result was zero. Z = 0 means it was not zero.

Predict it. Take those first three steps. A and address 4 hold 2. Should Z be set or clear?

Show an explanation

Z is clear: 3 − 1 = 2, and 2 is not zero. The store preserves the flag set by the subtraction.

Subtract and store ↑

Is there anything left?

The jump is JNZ 0103H: jump if not zero. It tests Z, just as the previous lesson’s JNC tested carry.

  • Z = 0: the result was not zero, so return to the subtraction at 0103.
  • Z = 1: the result was zero, so continue after the jump at 010B.

Take the jump and go around again. A becomes 1, which is still not zero. On the third trip, A becomes 0 and Z becomes 1. The last jump falls through.

Count the trips. How many times does each instruction run? How many presses of Step does the whole program need?

Show an explanation

The load runs once. Subtract, store, and jump each run three times: ten instructions altogether. The jump executes on the last trip too, even though it does not go backward.

Finish the countdown ↑

The stored results are 2, 1, then 0. The lesson stops offering steps at 010B; the CPU has left the loop without executing a halt instruction.

What Z remembers.

In this program, the subtraction updates Z. Loading, storing, and jumping leave it alone. Z records a calculation’s result; it does not continuously check the current contents of A or memory.

That is why A and Z both start at 0 in this experiment: we initialized them that way. No subtraction has run yet.

Try it. Start again and step until the third store has written 0. Before the final jump, change address 4 to 99. Does the countdown continue?

Show an explanation

No. A is still 0 and Z is still 1. JNZ reads Z and falls through. Your 99 remains in memory because there is no later store.

Change memory before the jump ↑

Choose a count.

Start again, then change address 3 before loading. Try 1 for one trip through the loop, or 5 for five trips. Each trip subtracts one, stores it, and tests Z.

Changing address 3 after the load does not change the countdown already in A. The jump returns to the subtraction, so the load runs only once.

What if the starting count is zero?

This program subtracts before it tests. Loading 0 does not set Z. The first subtraction, 0 − 1, wraps to 255 in a byte, and sets Z to 0 because that result is not zero.

The loop then counts down from 255. It takes 256 trips altogether to reach zero again. You can try the first few steps and use Start again without finishing that long run. Checking before doing the work would require a different program.

For starting counts from 1 to 255, we now know exactly how many times the loop repeats. A small number in memory controls how much work the program does.
