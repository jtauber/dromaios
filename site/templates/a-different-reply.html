Meet the Altair · Choosing a reply

A different
reply.

So far, the computer has sent back exactly what it received. Now let the program make a choice: reply to lowercase a with uppercase A, and leave every other character alone.

Begin here: Lowercase a is prepared below. Send it, then step four instructions to receive it. The register A holds 97, and the text display is still empty. The next instruction asks whether this is the character we want to change.

Ask about the byte you received.

The first four instructions are familiar: check readiness, compare with zero, decide whether to keep waiting, then receive a byte. The new work begins at 0109, after that byte reaches the register A.

Lowercase a is 97 decimal, or 61 hex. Uppercase A is a different byte: 65 decimal, or 41 hex. The register is also named A; it can hold either value.

CPI 61H compares the received byte with 97. As in our earlier comparison lesson, it sets the zero flag Z when the values match and clears Z when they differ. It leaves the value in A unchanged.

Predict it. With lowercase a received, step the comparison. Should A hold 97 or zero? What should Z be?

Show an explanation

A still holds 97. Z is 1 because 97 equals 97. The comparison records an answer in the flags; it does not replace the received character or send anything to the display.

Skip the change, or make it.

The next instruction is JNZ 0110H: jump if Z is zero. A byte that differs from lowercase a takes this jump straight to OUT. Its value in A stays unchanged.

For lowercase a, Z is 1, so the jump is not taken. Execution continues to MVI A,41H at 010E. This instruction copies the following byte, 65, into A. “Immediate” means the value is part of the instruction itself.

There is no output yet. MVI changes A from 97 to 65, while preserving the flags and RAM. The next instruction, OUT 01H, finally sends 65 to the display, where it appears as uppercase A.

Try the other path. After OUT, step once more to return to the readiness check. Send b and follow it through. Which instruction does the processor skip?

Show an explanation

It skips MVI at 010E. JNZ moves PC from 010B to 0110, so the replacement bytes are not fetched. OUT sends the original 98. Starting at 0100 with a byte ready, a reaches OUT in eight instructions; b reaches it in seven.

Each answer belongs to a particular question.

This program uses Z for two comparisons. At 0102, the question is “is the input device empty?” At 0109, it is “does the received byte equal 97?” The second comparison replaces the first answer.

After the reply, the program returns to checking readiness. A may then hold 0 or 1, and Z describes that new comparison. The output text remains. Use the captured instruction history to inspect the earlier decision.

Keep two bytes separate. Receive lowercase a, then send b before the comparison. Predict the first reply.

Show an explanation

The reply is uppercase A. The CPU compares the 97 already in its register; b waits separately in the device. On the next trip, the program receives b and echoes it unchanged.

Test the rule with unfamiliar input.

Try A, z, a digit, punctuation, a space, and line feed. Then try a again. Only lowercase a should change; this program does not convert all lowercase letters to uppercase.

For a longer experiment, RUN and send the characters of “a cat” one at a time, waiting for room in the device. Predict the whole reply before reading the explanation.

Show an explanation

The reply is “A cAt”. Both lowercase a bytes become uppercase A, while the space, c, and t pass through unchanged. Repeated output bytes still produce repeated characters.

The input and display are the same teaching devices as before. The difference is in the program bytes loaded into RAM. The CPU compares numbers and follows instructions; the display still only presents the bytes sent by OUT.

STOP keeps the current decision, pending input, and output intact. Start this lesson again clears the experiment and prepares lowercase a. As before, the text display keeps the latest 256 output bytes. The reference card shows the complete fixed program; changing a program byte pauses execution until it is restored.
