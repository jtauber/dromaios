Memory and the processor · Comparing values

Choosing a
stopping point.

We can count down to zero. But what if we want to count up to 44? The processor can compare two numbers without changing either one.

{{ register_explorer('comparison-memory', 41, 0, machine='comparison', program=true, edit_operand=true) }}

Have we reached 44?

The first three instructions are familiar: load 41 into A, add one, and store the result at address 4. A and address 4 now hold 42.

The next instruction is new: CPI 44, meaning compare A with 44. It asks whether the two numbers are equal. The answer appears in the zero flag, Z.

Predict it. Take those first three steps, then the comparison. What will A hold? What will Z be?

Show an explanation

A stays 42. Because 42 and 44 differ, Z is 0. Address 4 also stays 42; comparing does not write to memory.

Compare for the first time ↑

The familiar JNZ 0103H follows. With Z = 0 it returns to the addition. The next trip produces 43, which still differs from 44, so the loop repeats again.

Zero, without making A zero.

On the third trip, adding one makes A = 44. The store writes 44 to address 4. The comparison now sets Z to 1, and JNZ continues past the loop at 010D.

Why the zero flag? Comparing calculates A minus the target just to set the flags. When the numbers match, the difference is zero: 44 − 44 = 0. The processor discards that difference. A keeps 44.

Watch the distinction. On the last trip, check Z after the addition and again after the comparison. A holds 44 both times. Does Z?

Show an explanation

No. The addition clears Z because its result, 44, is not zero. The comparison sets Z because 44 − 44 is zero. A stays 44 throughout the store, comparison, and jump.

Finish at 44 ↑

The load runs once; add, store, compare, and jump each run three times. That is thirteen instructions, storing 42, 43, then 44. The lesson stops offering steps after the last jump; the CPU has not executed a halt instruction.

Choose your target.

Start again and change Compare A with this target to 43. The byte at 0109 changes from 2C to 2B: hexadecimal for 44 and 43. The instruction now says CPI 43.

CPI means compare immediate. Like the number in ADI, its target is a byte in the instruction itself. Editing it changes the program in memory; it does not execute the comparison.

Try it. How many trips will a target of 43 take? What about 42?

Show an explanation

Starting at 41, a target of 43 takes two trips, or nine instructions including the load. A target of 42 takes one trip, or five instructions. In each case, the stored result and A finish at the target.

Choose a different stopping point ↑

The target accepts 0–255 and locks after the first step. Start again restores the starting byte to 41, the target to 44, and all the records and counts to their initial state.

What if the target is 41, or less?

This program adds before it compares. A target of 41 therefore needs a whole trip around the byte’s range: 256 additions to reach 41 again. A lower target also requires passing through 255 and wrapping to 0.

For a short experiment, start again, set the target to 0, and change the byte at address 3 to 254 before loading. Two trips store 255, then 0. Each addition still adds exactly one.

An answer the jump can use.

Z remembers the last instruction that updated it. Both addition and comparison can change Z here. The comparison comes after the addition, so its answer is the one JNZ uses.

Try it. With the default target, pause after the last comparison: A = 44 and Z = 1. Change address 4 to 99, then take the jump. Will it repeat?

Show an explanation

No. The edit changes memory, but leaves A and Z alone. JNZ reads Z = 1 and falls through. Your 99 stays in memory because no later store runs.

Test the remembered answer ↑

We can now make a loop finish at a chosen number while keeping that number in A. Comparison supplies the answer; the jump chooses the path.
