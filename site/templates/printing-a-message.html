Meet the Altair · Following a pointer

Printing
a message.

The computer can send text without waiting for you to type. Store a message in RAM, then let a small loop read and send its bytes one at a time.

Begin here: HELLO and a line feed are already in memory. Step once to set HL to 0100. The first message byte becomes highlighted, but A and the display have not received it yet.

Keep an address in the processor.

The message occupies six consecutive locations, 0100 through 0105. Each holds one byte: H, E, L, L, O, and LF. Addresses and bytes in the memory window are hexadecimal.

We need somewhere to remember which location to read next. The 8080 combines two of its byte registers, H and L, into the sixteen-bit pair HL. H holds the high byte and L the low byte: H = 01 and L = 00 together give address 0100.

When a register value is used as an address, we call it a pointer. The first instruction, LXI H,0100H, puts the message’s starting address into HL. Setting an address does not read the byte stored there.

PC and HL have different jobs here. PC tracks where to fetch instructions; HL points to message data. This example puts its program at 0000 and its message at 0100. The panel lights still follow PC; the new memory window follows HL.

Predict it. With HL at 0100, will A hold 0100, 72, or its old value?

Show an explanation

A keeps its old value, initially zero. HL holds the address 0100. RAM at that address holds 48 hex, or 72 decimal: the ASCII byte for H. These are three separate values.

Set the pointer ↑

Read a byte. Then send it.

The second instruction, MVI B,06H, puts 6 into B. This is the number of bytes the loop will send, including line feed. B is another byte register; its role as a counter comes from this program.

The third instruction is MOV A,M. In this 8080 spelling, M means the memory location addressed by HL. It is not another register. The instruction reads the byte at 0100 into A, so A now holds 72. HL stays at 0100, and RAM keeps its byte.

The fourth instruction, OUT 01H, sends that 72 to the display. H finally appears. Loading the pointer, setting the count, and reading RAM produced no output.

Try it. Stop after MOV, then inspect the captured accesses. Where did the opcode come from, and where did the character come from?

Show an explanation

The processor fetched opcode 7E at 0005, then read the character byte 48 at 0100. Both reads came from RAM, but the bytes played different roles. The later OUT makes a separate transfer to output port 1.

Follow the first character ↑

Move the pointer, then repeat the work.

INX H adds one to the register pair HL. The highlight moves from 0100 to 0101. A still holds 72, and the output still reads H: advancing an address does not load the next character automatically.

DCR B subtracts one from the count, leaving 5 and clearing Z. JNZ 0005H returns to MOV while that count is nonzero. The loop reuses the same instructions, but MOV now reads through the new address in HL.

Each trip reads, sends, advances, counts down, and tests. The changes happen in that order. Just after OUT, the byte has been sent but B has not yet decreased; just after INX, HL has advanced but A still holds the previous byte.

Predict the next trip. After printing H, follow the loop back to 0005. Which RAM location will MOV read now, and what will appear after OUT?

Show an explanation

HL is 0101, so MOV reads 45 hex, or 69 decimal: E. After OUT the display reads HE. PC uses the same instruction addresses while HL advances through the data.

Follow the loop ↑

The two L bytes live at different addresses, 0102 and 0103. Each trip produces its own OUT transfer. Equal byte values still make two visible letters.

Let the count decide when to finish.

On the sixth trip, the byte at 0105 is LF. OUT moves the display to a new line. INX advances HL to 0106, just beyond the message window, and DCR leaves B at zero with Z = 1. The final JNZ continues past the loop.

The program does not use line feed as a stop signal. B decides how many bytes to send. If one of the six bytes changes, the loop still makes six trips.

The next instruction is HLT. This is the program telling the CPU to halt. PC advances to 000E, the halted indicator becomes yes, and RUN and Step become unavailable. The message and final state remain visible.

The viewer’s STOP button only pauses between instructions; RUN can resume that pause. HLT changes the CPU’s own state. EXAMINE can change PC but cannot release HALT. Use Start this lesson again to restore the complete example.

How many instructions ran?

Two setup instructions, six trips through a five-instruction loop, and one HLT: 33 instructions. Final HL is 0106, B is 0, A is 10 (LF), and PC is 000E. The output device received six writes, and the display reads HELLO followed by a new line.

Change the data, keep the program.

The memory window reads actual RAM. You can change the message with the familiar panel while stopped, leaving the instructions alone.

Try printing JELLO instead
  1. Start this lesson again.
  2. Set the panel switches to 0100 and press EXAMINE.
  3. Set the switches to 004A and press DEPOSIT. The first message byte changes from H to J; nothing is sent yet.
  4. Lower all switches and EXAMINE 0000 to return PC to the program.
  5. RUN, or step through it. Predict whether the instruction path and byte count will change.

The display prints JELLO and a line feed, using the same 33 instructions and six writes. Restart restores HELLO.

Only the message data changed. The same pattern—read through a pointer, advance it, and repeat—can also copy a buffer, add a series of numbers, or inspect a sequence of bytes.
