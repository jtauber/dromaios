BASIC on the Altair · From commands to programs

Your first
BASIC program.

Type a calculation and see the answer. Then ask the computer to remember a few instructions and carry them out together. You can start here without knowing any 8080 instructions.

First, give the computer BASIC.

This is the original 4K BASIC 3.2 interpreter running on our Altair. An interpreter is a program that reads your commands and carries them out. Before it can understand PRINT, the Altair must load that interpreter into memory.

  1. Get the selected paper-tape file from the machine guide (opens in a new tab). Return here and choose it in Paper tape below. The file stays on your computer.
  2. Raise only switches A11 and A10. Leave PC at 0000: do not press EXAMINE. You may then close the front panel to bring the terminal closer.
  3. Press the browser's RUN button. Click Terminal keyboard and answer each question when it appears:
BASIC's startup questions
When you seeEnter
MEMORY SIZE?Just Enter, to let BASIC find the available memory.
TERMINAL WIDTH?Just Enter, to keep the default.
WANT SIN?Y then Enter. We will not need this math function today.

When 727 BYTES FREE and OK appear, BASIC is ready. Leave the processor running for the rest of the lesson. Switching tabs pauses it; press the browser's RUN button when you return.

If you need to start loading again, use Reload tape, raise A11 and A10 again, then RUN. Reload discards the current BASIC program. Reset CPU + serial does not reload BASIC.

An answer now.

Click Terminal keyboard, type this command in uppercase, then press Enter:

PRINT 2+3

BASIC displays 5, then OK. The spaces around the answer are normal. Here, PRINT means “send the result to the terminal.”

This is an immediate command: BASIC does the calculation as soon as you submit the line. OK means it is ready for another command.

Try another sum. What will PRINT 2+8 display?

Show the answer

10, followed by OK. Changing the command changes the calculation.

Try it in the terminal ↑

Instructions for later.

Now type these three lines, pressing Enter after each one. If you paste, paste one line at a time. Wait until the complete line has appeared in the terminal before sending the next.

10 PRINT "HELLO"
20 PRINT 2+3
30 END

Each line begins with a line number. That tells BASIC to store the instruction for later. You see the line echoed, but you do not get HELLO, the answer 5, or a new OK yet. That is expected.

The line numbers are decimal labels, not memory addresses. BASIC uses their order to decide which instruction comes next. We have left gaps between them so there is room to insert another line later.

Quotation marks make "HELLO" a piece of text to print. Without quotation marks, 2+3 is a calculation. END marks the end of our program.

Made a typing mistake?

Before Enter, Backspace erases one character. BASIC echoes an underscore rather than rubbing the old character off the display. After Enter, type the whole numbered line again correctly: BASIC replaces the line with that number. If an immediate command produces an error, wait for OK and type it again.

Predict it. Why did PRINT 2+3 give an answer earlier, while 20 PRINT 2+3 did not?

Show an explanation

The leading 20 asks BASIC to remember the instruction. It has not been asked to run the stored program yet.

Enter the program ↑

Look, then run.

Type LIST and Enter. BASIC prints the three stored lines in line-number order, then OK. Check your program against the listing above. LIST shows what BASIC remembers; it does not execute those instructions.

Now type RUN and Enter. You should see:

HELLO
 5

OK

BASIC starts at the lowest line number. Line 10 prints the greeting, line 20 prints the sum, and line 30 returns control to BASIC. Type RUN again: the program is still there, so it produces the same result.

The typed BASIC command RUN starts your stored program. The browser's RUN button lets the processor execute instructions. Leave that processor running even at OK: BASIC needs it to receive your next command. END finishes your BASIC program without stopping the processor.

Compare two commands. Type LIST, then RUN. Which shows the instructions, and which carries them out?

LIST shows numbered source lines. RUN prints HELLO and 5 because those are the actions the lines describe.

Change one line.

Enter this replacement:

20 PRINT 2+8

Type LIST. There should still be three lines, with just one line numbered 20. Its calculation now reads 2+8; the greeting and END are unchanged.

Type RUN. This time the program prints HELLO, then 10, then returns to OK. Replacing one stored instruction changed what the program does.

Make it yours. Replace line 10 with 10 PRINT "HI". Predict the whole output, then RUN.

Show the answer

HI, then 10, then OK. Changing line 10 leaves line 20 alone.

Change your program ↑

A program running a program.

Earlier lessons followed individual 8080 instructions. Here those same kinds of instructions run BASIC: they read characters, store your lines, calculate, and print. Your BASIC program gives the interpreter work to do.

You can keep experimenting in the terminal. The program lives only in this page's current machine: navigating away, refreshing, or reloading the tape loses it. Copy your numbered lines somewhere if you want to keep them.

The machine guide (opens in a new tab) explains the hardware, loading process, and recovery controls. This lesson uses that same machine and original interpreter.
