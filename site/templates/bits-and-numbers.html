Eight bits.
One number.

A bit can be 0 or 1. Put eight together and you have a byte. Let’s see how those bits can represent a number.

Every position has a value.

Start at the right: 1, 2, 4, 8. Each position is worth twice the one before it. A 1 includes that value; a 0 leaves it out. Add the included values to find the number.

The starting byte has 32, 8, and 2 switched on. That makes 42.

Switch on 8, 4, and 1: 00001101. Their sum is 13.

Three ways to write the same number.

Binary uses two digits, 0 and 1. Each digit corresponds to one bit, so eight digits show the whole byte.

Decimal uses the ten digits we count with, 0 to 9. Here, we read the byte as an unsigned number: zero or a positive whole number.

Hexadecimal uses sixteen digits: 0 to 9, then A, B, C, D, E, and F for ten through fifteen. Each group of four bits fits into one hex digit, so two hex digits can describe a byte.

Binary 00101010, decimal 42, and hexadecimal 2A all describe the same value. The two extra zeroes at the start of the binary form keep all eight bit positions visible.

Try it. Enter F in the hexadecimal field. Then try F0. Watch which group of four bits changes.

Show an explanation

0F turns on the right-hand four bits: 8 + 4 + 2 + 1 = 15. F0 turns on the left-hand four: 128 + 64 + 32 + 16 = 240.

How much fits in one byte?

With all eight bits off, the number is 0. With all eight on, their values add up to 255. That gives us 256 different patterns, representing the unsigned numbers 0 through 255.

Try it. Enter 255 in decimal. Before switching off the leftmost bit, predict the new value.

Show an explanation

The leftmost bit contributes 128. Removing it leaves 255 − 128 = 127: binary 01111111, hexadecimal 7F.
