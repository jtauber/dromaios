Instructions are bytes too.

The commands are already stored in memory. They are bytes, just like the values at addresses 3 and 4. The descriptions beside them are for us; the processor reads the bytes themselves.

Look at “Add one to A.” Its two bytes are C6 01. On the 8080, C6 says to add a number to A; the next byte supplies that number. Here it is 01, meaning one.

The program view uses hexadecimal for both addresses and contents. Each small address labels one memory location; the larger number underneath is its byte. For example, location 0103 contains C6.

Both views above show parts of the same RAM: data near the beginning, and the program starting at 0100 (256 in decimal). This lesson lets you edit the data while keeping the instructions fixed.

An address to remember.

The processor has another register called the program counter, or PC. Between these steps, it holds the address where the next instruction begins.

Our lesson starts PC at 0100. Press Step one instruction. The processor fetches the load instruction from that address and executes it. A receives 41, and PC moves to 0103.

PC counts addresses, not instructions. The load occupies three bytes, at 0100, 0101, and 0102. The next instruction therefore starts at 0103.

Predict it. The addition begins at 0103 and occupies two bytes. Where will PC point after you step again?

Show an explanation

It moves to 0105. The addition uses the bytes at 0103 and 0104; the store starts immediately after them.

Fetch, then act.

Fetching means reading the instruction’s bytes from memory. The shaded bytes show what the last step fetched. The arrow shows where the next instruction starts. After a step, these refer to different instructions.

The load fetches 3A 03 00, then reads the data at address 3 into A. That data read is separate from fetching the instruction. You can see all four reads in the optional record above.

Why three bytes for the load?

3A selects the load instruction. The next two bytes give its address, with the low byte first: 03 00 means 0003. An 8080 memory address needs two bytes, while the value loaded into A is one byte.

Each press executes one whole instruction. The display reports the completed step; it does not pause at each byte read or represent individual clock cycles.

Try it. Start again. Open the byte editor and change address 3 to 255, then step through all three instructions. Does the path taken by PC change?

Show an explanation

No. PC follows 0100 → 0103 → 0105 → 0108 again. A and carry change because the data is different, but the program’s bytes and instruction lengths stay the same.

At the end.

The store occupies three bytes, so the final step leaves PC at 0108. Our lesson stops offering steps there. The processor has not executed a halt instruction; we have reached the end of this little experiment.

You have followed a stored program: instruction bytes tell the processor what to do, and PC tells it where to look next. Here, each instruction leads to the following one. Later, we will see instructions that deliberately change that path.
