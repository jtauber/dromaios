Meet the Altair · A byte arrives

Receiving
a byte.

The computer can send a byte out. Now give it a byte to receive. Follow the value from your switches, through an input device, into A, and finally to the lamps.

Begin here: 42 is prepared on the input switches. Press Send byte to device, then Step one instruction twice. Watch where the byte is waiting after each action.

{{ altair_panel(mode='input') }}

Preparing is not sending.

These eight input switches belong to our new teaching device. They are separate from the Altair memory panel below. Moving them prepares a number; it does not change RAM, A, or either device’s stored byte.

Press Send byte to device. Now the device holds the byte, waiting for the processor to read it. A still holds zero, and the output lamps have received nothing.

Try it. Send 42, then change the switches to a different number. Does the waiting byte change?

Show an explanation

No. Sending copied the value at that moment. The waiting byte stays 42. The switches can prepare another byte, but Send is disabled while the device is full, so you cannot overwrite one that has not been read.

Prepare and send a byte ↑

Receive it. Then echo it.

The first instruction is IN 01H: receive a byte from input port 1 into A. This device hands over its waiting byte and becomes empty. The input switches keep their positions.

The second instruction is the familiar OUT 01H: send A to the lamp device. It now displays the byte you supplied. Sending received data back out is called echoing.

Both instructions use port number 1, but their directions choose different connections: IN reads the input device, and OUT writes the output device. Neither accesses RAM address 1; its readout stays zero.

Predict it. After IN, A holds 42 and the input device is empty. Have the output lamps received 42 yet?

Show an explanation

Not yet. IN only receives the byte. The lamps change when the next instruction, OUT, sends it. The processor performs each transfer separately.

Step through both transfers ↑

Open Look inside the last instruction after each step. The trace shows the instruction bytes fetched from RAM, followed by an input or output transfer. The values there are hexadecimal: 42 decimal is 2A.

Another byte can wait its turn.

As soon as IN empties the input device, Send becomes available again. You can send your next prepared byte before OUT runs. That new byte waits in the device; it does not replace the first one already in A.

Try receiving 42, then sending 99 to the input device before the echo. Prepare 99 by raising only input switches 6, 5, 1, and 0: 01100011. OUT still sends 42. The input device keeps 99 for later.

The two-instruction program ends at 0104. To receive the next waiting byte, raise only switch 8 on the Altair memory panel and EXAMINE 0100. Then step or RUN again. EXAMINE changes PC but leaves both devices alone.

STOP also preserves the waiting input, A, and the output lamps. Sending input never starts execution automatically. You choose when to step or RUN.

Zero is a byte too.

Lower all eight input switches and send zero when the device has room. It now says “Waiting: 0,” which is different from “Device empty.” IN receives that zero into A; OUT sends it to the lamps. All eight lamps go dark, and the write count increases.

For this first lesson, the controls pause before IN if no byte is waiting. The message asks you to send one, then step or RUN. This pause is a teaching aid: it is not an instruction, and it does not change the CPU’s state.

The underlying input device would return zero if read while empty. A real program using this device must check whether a byte is ready to distinguish an empty read from a received zero. The next lesson makes that check part of the program.

What this view models

The input device stores one waiting byte; it has no queue. These input switches and the separate lamp device are teaching illustrations, not particular historical Altair peripherals. Both devices are connected through the machine’s ports. RUN, STOP, and stepping work at whole-instruction boundaries; physical timing and bus signals remain outside this view. Stopping at 0104 is a lesson boundary, not a halt instruction. Start this lesson again restores the program, empties both devices, clears the counts and history, and prepares 42 on the input switches.
