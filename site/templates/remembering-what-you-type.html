Meet the Altair · Writing through a pointer

Remembering
what you type.

A character need not be printed as soon as it arrives. The program can save several characters in RAM, then read them back when the message is ready.

Begin here: Send the prepared H while stopped. Step eight times to receive it and check that it is not LF. A holds 72, but RAM and the display are unchanged. The ninth instruction, MOV M,A, makes the first stored character appear in the buffer.

A place to keep the characters.

A buffer is a region of memory used to hold data. Our program uses 0100–0107 for up to eight characters, with one extra location at 0108 available for the zero terminator. All nine locations start at zero.

LXI H,0100H puts the first buffer address into HL. MVI B,08H puts the capacity into B. During collection, HL points to the next place to write, and B counts the character slots still available.

The input device still holds only one pending byte. The larger buffer is ordinary RAM, filled by the program. Typing or pressing Send does not write to it.

Predict it. After IN receives H into A, what changes in the buffer?

Show an explanation

Nothing yet. IN consumes the device’s byte and puts 72 in A. A separate instruction must store that value in RAM.

Follow the first character ↑

Use the pointer in the other direction.

You have seen MOV A,M read through HL. MOV M,A copies in the other direction: from A into the memory location addressed by HL. M still means “the byte at HL.”

The first store writes 48 hex, or 72 decimal, at 0100. A keeps 72, HL stays at 0100, and the display stays empty. INX H then advances HL to 0101; DCR B reduces B from 8 to 7. These are separate changes.

If B is not zero, JNZ returns to the readiness check. The program can keep polling while you prepare the next character. Readiness checks change A, but the stored H remains in RAM.

Look inside the store. Which address supplied the instruction, and which address received the character?

The CPU fetched opcode 77 at 0013, then wrote 48 at 0100. The captured record shows a memory write, with no output-port transfer.

Store, advance, and count ↑

Tell the program the message is ready.

After IN 01H receives a byte, the CPU compares it with 10 decimal, the value of LF. For this program, LF means finish collecting. It skips the character store, so LF takes no slot and does not enter the buffer.

The CPU puts zero into A, stores it through HL, and resets HL to 0100. This appends NUL after the characters and brings the pointer back to the start. Even though unused RAM already starts at zero, the program explicitly writes its terminator.

The familiar print loop now reads through HL, compares with zero, and sends each nonzero byte. Only these OUT instructions put text on the display. It halts at NUL; neither LF nor NUL is printed.

Try it. Collect H and I, then send line feed.

A gentle walkthrough
  1. Start this lesson again, then RUN at a comfortable pace.
  2. Send H. Prepare I, wait until the input device is empty, then send it.
  3. Wait for the device to be empty again and press Send line feed.
  4. Watch the program finish the buffer, rewind HL, and print HI.

RAM begins 48 49 00. B finishes at 6, HL at 0102, A at zero, and PC at 002C. The display has received two writes. Pressing Enter in the character field sends that character; the separate line-feed button ends collection.

Collect a short message ↑

Sending LF first makes an empty message. The program stores NUL at 0100, then halts without executing OUT.

Keep room for the ending.

After the eighth character, DCR leaves B at zero. JNZ does not return for more input. The program immediately appends NUL at 0108 and prints the eight stored characters, without waiting for LF.

The extra location matters: eight characters and a terminator require nine bytes. During normal execution from the start, the program never writes past 0108. B is decreased after the store, so it may briefly show its old value beside a newly written character.

You can prepare or offer another character while the CPU finishes. A later offer may wait in the input device, but this run will not receive or store it. Starting the lesson again clears that pending byte and the buffer.

Try a full buffer. Send ABCDEFGH, one character at a time. Does printing need a ninth input byte?

Show an explanation

No. The capacity check starts playback after H. The nine RAM bytes are 41 42 43 44 45 46 47 48 00. A ninth character offered after H is received stays pending; it cannot replace the terminator.

Fill all eight slots ↑

The output comes from memory.

Once a character has been stored, later typing does not change it. The readback loop obtains its bytes from RAM, not from the input field or a hidden copy of your text.

Change stored H to J before playback

Collect HI and send LF. Step until PC is 001F, just before the first readback MOV. STOP if running. EXAMINE 0100, set the switches to 004A, and DEPOSIT. Then EXAMINE 001F to restore PC and continue. The display prints JI. Editing RAM after that MOV would leave the first character already captured in A unchanged.

The switches remain available for experiments, but manually jumping into the middle of collection can bypass the setup and capacity check. Start again to return to the program’s normal path.

The character field offers printable ASCII, including spaces. LF is sent separately. The raw byte device can accept other values; a stored NUL would end readback early because this format uses zero as its terminator.
