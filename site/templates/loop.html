around again.

A jump can take us back to an earlier instruction. What happens when the processor adds one, stores the result, and then does it again?

The first time around.

Take three steps. The load puts 41 into A, the addition makes it 42, and the store writes 42 to address 4. We have done all of this before.

Now PC points to 0108, where the instruction is JMP 0103H. Take one more step. The next-instruction marker returns to the addition at 0103.

Predict it. What does A hold after the jump? What will the next addition produce?

Show an explanation

A still holds 42. The jump changed PC, not A. The next addition therefore makes A 43. Address 4 keeps 42 until the next store writes 43 there.

Go around again ↑

Repeat without resetting.

The processor repeats three instructions: add, store, jump. Together they form a loop. The same bytes run again, working with the state left by the previous trip around.

Watch the run counts. The load stays at 1, while the other instructions run again and again. PC revisits 0103 → 0105 → 0108 → 0103, but the stored results grow: 42, 43, 44…

The recent PC path shows up to twelve steps. Earlier addresses disappear from that short history, but each instruction’s run count continues to include the whole experiment.

Try it. After the load has run, open the byte editor and change address 3 from 41 to 99. Does the next trip around the loop start from 99?

Show an explanation

No. The backward jump goes to the addition, after the load. A keeps its working value. Changing address 3 would matter if the load ran again, but this loop never returns to it.

Change the starting data ↑

Start again does something different from the jump: it restores the whole lesson, including A = 0, the starting data, PC = 0100, and cleared run counts.

Still one byte.

Repeating the addition does not make A any wider. Eventually the value reaches 255 and the next addition wraps to 0, setting carry.

Take a shortcut. Start again and change address 3 to 254 before the load. Step through the program until it stores 255, then go around once more. What gets stored next?

Show an explanation

The next addition makes A = 0 and CY = 1; the store writes 0. Store and jump preserve that carry. One more addition makes A = 1 and clears CY again.

Follow 254 → 255 → 0 → 1 ↑

The jump always goes back, even when the value wraps or carry changes. It does not test a flag.

When does it stop?

This program has no instruction that ends the loop. Every jump leads back to the addition.

In this experiment, you control the pace: each press runs one whole instruction, and nothing runs between presses. You can pause simply by stopping. Step remains available, and Start again restores the original setup.
