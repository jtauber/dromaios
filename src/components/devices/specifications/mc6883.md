# Motorola MC6883: the CoCo's address and video control

The Synchronous Address Multiplexer, or SAM, lets the 6809 and video generator
share dynamic RAM. It supplies multiplexed DRAM addresses, refresh, clock
division, memory selection, and the address sequence consumed by the VDG.
Motorola's [MC6883/SN74LS783 datasheet][manual] describes these coupled jobs.
The [CoCo chapter](../../../machines/6809/coco.md) selects a deliberately
smaller, untimed model: register writes and display addressing, with a fixed
32 KiB logical RAM connection. DRAM row/column multiplexing, refresh, bus
contention, and E/Q clocks are not simulated.

## Sixteen bits, thirty-two write addresses

The SAM has no readable data registers. Writes to FFC0–FFDF select a bit by
address alone: an even address clears it, the following odd address sets it.
The written data byte is irrelevant. Physical reset clears **all** bits;
firmware, rather than construction, selects the familiar 0400 screen page.

| Control bits | Addresses | Meaning |
| --- | --- | --- |
| 2:0, V | FFC0–FFC5 | Display address sequence |
| 9:3, F | FFC6–FFD3 | Display start, in 512-byte units |
| 10, P1 | FFD4–FFD5 | CPU RAM page in a 64 KiB configuration |
| 12:11, R | FFD6–FFD9 | CPU clock selection |
| 14:13, M | FFDA–FFDD | DRAM organization |
| 15, TY | FFDE–FFDF | Normal ROM map or all-RAM map |

```device
device "mc6883"

state {
  register CONTROL: 16
}

action reset "Reset all sixteen SAM control bits" {
  CONTROL <- u16($0000)
}

source validState "Every sixteen-bit control word is representable" : flag {
  return 1
}

source writeControl "Address A4:A1 selects a bit; A0 supplies its value" (address: 8, byte: 8): flag {
  low = select(bit(address, 1), u16($0002), u16($0001))
  pair = select(bit(address, 2), shiftBits(low, left, 2), low)
  nibble = select(bit(address, 3), shiftBits(pair, left, 4), pair)
  mask = select(bit(address, 4), shiftBits(nibble, left, 8), nibble)
  control = register CONTROL
  CONTROL <- select(bit(address, 0), or(control, mask), and(control, xor(mask, u16($FFFF))))
  return 1
}
```

The four selections above decode A4:A1 into a one-hot mask, without a table
of thirty-two nearly identical handlers. Reads leave state untouched and are
unanswered; the board owns the undriven-bus policy.

## Inspection and the selected memory profile

M=00 selects 4K-by-1 DRAM organization, M=01 16K-by-1, M=10 64K-by-1,
and M=11 static-memory operation. Two banks of 16K-by-1 chips provide this
machine's 32 KiB. P1 has no effect with 32 KiB or less on the LS783/MC6883;
Color BASIC nevertheless sets it during initialization. The LS785 variant's
different uses of that bit are not part of this model.

R=00 selects the slow clock, R=01 an address-dependent rate, and R=1x the
fast clock. These bits are retained for inspection but do not change instruction
budgets into hardware time. TY=1 and M=1x remain stored and inspectable, but
the native machine refuses to execute in these unsupported configurations.
The startup M=00 state is retained; its physical DRAM aliasing is not modeled.

```device
source videoMode "Inspect V2:V0" : 8 {
  control = register CONTROL
  return truncate(and(control, u16($0007)), 8)
}

source displayStart "F6:F0 selects a 512-byte boundary" : 16 {
  control = register CONTROL
  return shiftBits(and(control, u16($03F8)), left, 6)
}

source page "Inspect P1" : flag {
  control = register CONTROL
  return bit(control, 10)
}

source clockMode "Inspect R1:R0 without inventing elapsed time" : 8 {
  control = register CONTROL
  return truncate(and(shiftBits(control, right, 11), u16($0003)), 8)
}

source memoryMode "Inspect M1:M0" : 8 {
  control = register CONTROL
  return truncate(and(shiftBits(control, right, 13), u16($0003)), 8)
}

source normalMap "TY clear selects the ROM-based address map" : flag {
  control = register CONTROL
  return not(bit(control, 15))
}

source supportedMemory "Normal ROM map with startup or 16K DRAM organization" : flag {
  control = register CONTROL
  return not(or(bit(control, 15), bit(control, 14)))
}
```

## A text page in physical RAM

For V=000, each of sixteen character rows supplies 32 bytes, repeated for
twelve raster lines. A frame renderer evaluates the current start address
and reads RAM directly. It does not run those reads through the CPU map:
even a high F value cannot access PIAs, acknowledge interrupts, or read ROM.
The selected 32 KiB backing store discards address bit 15. Coordinates outside
rows 0–15 and columns 0–31 are not visible cells.

Hardware loads the display counter at a field boundary and advances it with
VDG timing. This untimed view takes an instantaneous frame instead; changes
halfway through a scan, refresh addresses, and V=001–111 are future work.

```device
source textAddress "Address a cell within the selected 32 KiB physical RAM" (row: 8, column: 8): 16 {
  start = source displayStart()
  offset = add(shiftBits(extend(row, 16), left, 5), extend(column, 16))
  return and(add(start, offset), u16($7FFF))
}

interface Mc6883 {
  size 32
  initialize reset
  reset reset
  validate validState
  write * writeControl
  view videoMode
  view displayStart
  view page
  view clockMode
  view memoryMode
  view normalMap
  view supportedMemory
  view textAddress
}
```
