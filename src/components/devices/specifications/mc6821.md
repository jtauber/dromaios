# Motorola MC6821: parallel ports and control lines

The MC6821 Peripheral Interface Adapter connects a processor bus to two
eight-bit ports, A and B, and four control pins. Software chooses each port
bit's direction independently. Two PIAs connect the CoCo's keyboard, video
controls, and other board signals to its 6809. The chip has no knowledge of
keyboard characters, memory addresses, or the processor's IRQ/FIRQ routing.

This chapter implements the register and pin behavior needed by the first
[CoCo profile](../../../../docs/machines/coco.md). The authority is Motorola's
[MC6821 datasheet][manual], especially the peripheral-interface description
and Figure 18. All interrupt-input modes and software-controlled CA2/CB2
outputs are supported. The two hardware-strobe output modes are **rejected**
before changing state: their A/B handshake differences and E-clock timing
remain future work. There are no automatic sync pulses or electrical delays.

## Registers and external signals

The four local addresses select six registers. Control bit 2 selects the
direction register (0) or peripheral data (1) at the even address:

| Address | Read | Write |
| --- | --- | --- |
| 0 | DDRA or port A pins | DDRA or output latch ORA |
| 1 | CRA and interrupt flags | CRA bits 5:0 |
| 2 | DDRB or port B data | DDRB or output latch ORB |
| 3 | CRB and interrupt flags | CRB bits 5:0 |

A direction bit of 1 enables that output driver. A write to a data latch
retains **all** eight bits, including those currently configured as inputs.
Changing direction therefore exposes a previously written value immediately.

```device
device "mc6821"

state {
  register ORA: 8
  register ORB: 8
  register DDRA: 8
  register DDRB: 8
  register CRA: 8
  register CRB: 8
  register INPUT_A: 8
  register INPUT_B: 8
  latch CA1
  latch CA2
  latch CB1
  latch CB2
  latch IRQA1
  latch IRQA2
  latch IRQB1
  latch IRQB2
}

action resetRegisters "Reset the chip without moving external pins" {
  ORA <- u8($00)
  ORB <- u8($00)
  DDRA <- u8($00)
  DDRB <- u8($00)
  CRA <- u8($00)
  CRB <- u8($00)
  IRQA1 <- 0
  IRQA2 <- 0
  IRQB1 <- 0
  IRQB2 <- 0
}

action initialize "Start reset, with external connections released high" {
  perform resetRegisters()
  INPUT_A <- u8($FF)
  INPUT_B <- u8($FF)
  CA1 <- 1
  CA2 <- 1
  CB1 <- 1
  CB2 <- 1
}
```

Construction's high input levels are a deterministic disconnected convention,
not a universal electrical property of the chip. The board supplies external
levels through `setPortInputs`, `setCA1`, `setCA2`, `setCB1`, and `setCB2`.
Reset clears the chip's registers and flags, but preserves those external
levels. Resetting a chip does not release a held keyboard key or manufacture
an edge on a sync input. CPU-only reset need not reset a PIA at all.

## Port drivers and readback

`driveA` and `driveB` return a released-high mask: input bits are 1, output
bits contain the latch. External input masks then pull selected lines low.
This digital low-dominant resolution is enough for the keyboard; voltages,
drive strengths, and conflicting output currents are not modeled.

Port A reads the resulting pins even when configured as output. Port B
instead reads its **output latch** for output bits and its pins for input
bits. Thus externally pulling an output high bit low changes A's readback
but not B's. Inspection uses these pure views and never acknowledges a flag.

```device
source releasedHigh "Resolve enabled output bits and released input bits" (output: 8, direction: 8): 8 {
  return or(output, xor(direction, u8($FF)))
}

source driveA "Port A output drivers with inputs released" : 8 {
  output = register ORA
  direction = register DDRA
  result = source releasedHigh(output, direction)
  return result
}

source driveB "Port B output drivers with inputs released" : 8 {
  output = register ORB
  direction = register DDRB
  result = source releasedHigh(output, direction)
  return result
}

source pinsA "Resolved port A pins" : 8 {
  drive = source driveA()
  external = register INPUT_A
  return and(drive, external)
}

source pinsB "Resolved port B pins" : 8 {
  drive = source driveB()
  external = register INPUT_B
  return and(drive, external)
}

source dataB "Port B input pins and output-latch readback" : 8 {
  output = register ORB
  direction = register DDRB
  external = register INPUT_B
  return or(and(output, direction), and(external, xor(direction, u8($FF))))
}

action setPortInputs "Apply external levels without a guest transfer" (a: 8, b: 8) {
  INPUT_A <- a
  INPUT_B <- b
}
```

## Control words and interrupt levels

| Bits | Meaning |
| --- | --- |
| 7, 6 | Read-only interrupt flags for C1 and C2 |
| 5 | C2 direction: 0 input, 1 output |
| 4:3, with bit 5 clear | C2 active edge (0 falling, 1 rising), interrupt enable |
| 4:3, with bit 5 set | 10 forces C2 low; 11 forces it high; 00/01 strobe modes are deferred |
| 2 | Select data rather than direction register |
| 1:0 | C1 active edge (0 falling, 1 rising), interrupt enable |

Flags latch on the selected edge even when their interrupt enable is clear.
Enabling an already pending flag asserts the corresponding IRQ immediately;
disabling it removes that contribution without clearing the flag. The views
`irqA`, `irqB`, and `irq` mean **asserted**, although the physical IRQ outputs
are active low. A board samples these current levels rather than copying a
request into a second latch.

```device
source supportedControl "Input or software-controlled C2 output" (control: 8): flag {
  return or(not(bit(control, 5)), bit(control, 4))
}

source controlValue "Combine writable control bits with pending flags" (control: 8, first: flag, second: flag): 8 {
  return or(control, pack<8>(first, second, 0, 0, 0, 0, 0, 0))
}

source controlA "Inspect CRA and its flags" : 8 {
  control = register CRA
  first = latch IRQA1
  second = latch IRQA2
  result = source controlValue(control, first, second)
  return result
}

source controlB "Inspect CRB and its flags" : 8 {
  control = register CRB
  first = latch IRQB1
  second = latch IRQB2
  result = source controlValue(control, first, second)
  return result
}

source interruptLevel "Enabled pending inputs assert IRQ" (control: 8, first: flag, second: flag): flag {
  return or(and(first, bit(control, 0)), and(second, and(not(bit(control, 5)), bit(control, 3))))
}

source irqA "Section A asserts its interrupt output" : flag {
  control = register CRA
  first = latch IRQA1
  second = latch IRQA2
  result = source interruptLevel(control, first, second)
  return result
}

source irqB "Section B asserts its interrupt output" : flag {
  control = register CRB
  first = latch IRQB1
  second = latch IRQB2
  result = source interruptLevel(control, first, second)
  return result
}

source irq "Either open-drain interrupt output asserts the board line" : flag {
  a = source irqA()
  b = source irqB()
  return or(a, b)
}

source configureA "Write CRA without writing its read-only flag bits" (byte: 8): flag {
  supported = source supportedControl(byte)
  when supported {
    CRA <- and(byte, u8($3F))
    when bit(byte, 5) {
      IRQA2 <- 0
    }
  }
  return supported
}

source configureB "Write CRB without writing its read-only flag bits" (byte: 8): flag {
  supported = source supportedControl(byte)
  when supported {
    CRB <- and(byte, u8($3F))
    when bit(byte, 5) {
      IRQB2 <- 0
    }
  }
  return supported
}
```

Switching C2 to output clears its IRQ2 flag and disconnects edge detection.
Changing the edge-selection bits while an input is held does not synthesize an
edge. Input calls represent successive settled levels, separated sufficiently
for edge sensing; E-clock qualification and sub-cycle pulses are not modeled.

```device
source activeEdge "A transition ends at the selected active level" (before: flag, after: flag, rising: flag): flag {
  return and(xor(before, after), not(xor(after, rising)))
}

action setCA1 "Apply a new CA1 level" (high: flag) {
  before = latch CA1
  control = register CRA
  edge = source activeEdge(before, high, bit(control, 1))
  when edge {
    IRQA1 <- 1
  }
  CA1 <- high
}

action setCB1 "Apply a new CB1 level" (high: flag) {
  before = latch CB1
  control = register CRB
  edge = source activeEdge(before, high, bit(control, 1))
  when edge {
    IRQB1 <- 1
  }
  CB1 <- high
}

action setCA2 "Apply the external CA2 level; outputs cannot set IRQ2" (high: flag) {
  before = latch CA2
  control = register CRA
  edge = source activeEdge(before, high, bit(control, 4))
  when and(not(bit(control, 5)), edge) {
    IRQA2 <- 1
  }
  CA2 <- high
}

action setCB2 "Apply the external CB2 level; outputs cannot set IRQ2" (high: flag) {
  before = latch CB2
  control = register CRB
  edge = source activeEdge(before, high, bit(control, 4))
  when and(not(bit(control, 5)), edge) {
    IRQB2 <- 1
  }
  CB2 <- high
}

source ca2High "CA2 input level or software-controlled output" : flag {
  control = register CRA
  external = latch CA2
  return or(and(bit(control, 5), bit(control, 3)), and(not(bit(control, 5)), external))
}

source cb2High "CB2 input level or software-controlled output" : flag {
  control = register CRB
  external = latch CB2
  return or(and(bit(control, 5), bit(control, 3)), and(not(bit(control, 5)), external))
}
```

## Guest transfers and acknowledgement

Only a **data read** clears that side's two interrupt flags. Reading its
direction or control register, writing any register, or inspecting the device
does not acknowledge them. The exception is C2's transition into output mode,
described above. Reading port A never clears a port B request.

```device
source readA "Read DDRA or sample A and acknowledge its flags" : 8 {
  control = register CRA
  direction = register DDRA
  pins = source pinsA()
  when bit(control, 2) {
    IRQA1 <- 0
    IRQA2 <- 0
  }
  return select(bit(control, 2), pins, direction)
}

source readB "Read DDRB or sample B and acknowledge its flags" : 8 {
  control = register CRB
  direction = register DDRB
  data = source dataB()
  when bit(control, 2) {
    IRQB1 <- 0
    IRQB2 <- 0
  }
  return select(bit(control, 2), data, direction)
}

source writeA "Write DDRA or the entire A output latch" (byte: 8): flag {
  control = register CRA
  when bit(control, 2) {
    ORA <- byte
  }
  when not(bit(control, 2)) {
    DDRA <- byte
  }
  return 1
}

source writeB "Write DDRB or the entire B output latch" (byte: 8): flag {
  control = register CRB
  when bit(control, 2) {
    ORB <- byte
  }
  when not(bit(control, 2)) {
    DDRB <- byte
  }
  return 1
}
```

## State, inspection, and public interface

Snapshots include the external input levels as well as registers and pending
flags, so restoring and repeating a held level cannot invent an edge. Restoring
does not call reset or acknowledge a request. Invalid widths, Boolean fields,
reserved control bits, unsupported modes, and an IRQ2 flag on an output reject
restoration. All host arguments are checked before any effect.

```device
source validSide "Stored control bits and C2 flag obey the profile" (control: 8, second: flag): flag {
  supported = source supportedControl(control)
  return and(supported, and(equal(and(control, u8($C0)), u8($00)), not(and(bit(control, 5), second))))
}

source validState "Validate both sides without repairing their state" : flag {
  a = register CRA
  b = register CRB
  a2 = latch IRQA2
  b2 = latch IRQB2
  validA = source validSide(a, a2)
  validB = source validSide(b, b2)
  return and(validA, validB)
}

interface Mc6821 {
  size 4
  initialize initialize
  reset resetRegisters
  validate validState
  input setPortInputs
  input setCA1
  input setCA2
  input setCB1
  input setCB2
  view driveA
  view driveB
  view pinsA
  view pinsB
  view dataB
  view controlA
  view controlB
  view irqA
  view irqB
  view irq
  view ca2High
  view cb2High
  read 0 readA
  read 1 controlA
  read 2 readB
  read 3 controlB
  write 0 writeA
  write 1 configureA
  write 2 writeB
  write 3 configureB
}
```

The board owns address aliases and resamples the pure output views after either
a latch or direction write. There is no data-write-only callback that could
miss a direction change. Guest reads, pure views, and explicit input actions
remain distinct operations.

edge polarity, masked pending flags, acknowledgement, direction/latch order,
readback differences, rejected modes, and restoration against literal results.
