# Intel 8088

This executable guide defines Dromaios's original Intel 8088: every documented
instruction, stored state, register views, reset, execution, external interrupt
acceptance, and public interface. The generated emulator and its integration
metadata come from the `cpu` blocks; the surrounding prose explains the chip,
its host contracts, evidence, and instruction-level limitations.

## Historical background

Intel introduced the 8088 in 1979, following the 8086 in 1978. It retains the
8086's sixteen-bit programmer's architecture while using an eight-bit external
data bus. IBM chose the 8088 for the IBM PC, introduced in August 1981.
Intel's [processor chronology][chronology] and [account of the IBM PC][history]
provide the historical context; its [family manual][manual] describes the
architecture and instruction encodings used here.

That eight-bit bus does not make AX an eight-bit register. A word calculation
still operates on sixteen bits; transferring a word to memory takes two byte
transfers. The physical processor separates instruction execution from bus
activity and uses a four-byte instruction queue. Dromaios models ordered
instruction effects, without a prefetch queue or clock timing. Its recorded
accesses therefore describe the emulator's observations, not a cycle trace.

## The programmer's machine

| Registers | Role |
| --- | --- |
| AX, BX, CX, DX | Word registers with independently addressable low/high bytes |
| SP, BP, SI, DI | Word registers used for stacks, addressing, and string operations |
| CS, DS, SS, ES | Segment registers supplying the base of a 64 KiB address window |
| IP | Offset of the next instruction within CS |
| FLAGS | Arithmetic results and the TF/IF/DF control flags |

AL and AH are views of AX's low and high bytes. If AX is `$1234`, AL is `$34`
and AH is `$12`. Writing `$56` to AL gives AX=`$1256`; there is no separate
AL value to synchronize. The same relationship holds for BX, CX, and DX.
SP, BP, SI, and DI do not have separately addressable byte halves on this chip.

A memory address combines a segment and offset: shift the segment left four
bits, add the sixteen-bit offset, and keep the low twenty bits. Thus
`1234:0010` and `1235:0000` both select physical `$12350`. At the top of the
address space, `FFFF:0010` wraps to zero. IP wraps within its segment;
advancing it does not carry into CS. The snapshot's `pc` is a derived physical
CS:IP view; the execution contract below selects segmented instruction fetching.

Immediate words and memory words are little-endian: `MOV AX,1234H` is encoded
`$B8 $34 $12`. Here `$` introduces hexadecimal, while binary opcode patterns
run from most to least significant bit. Register selectors follow the
hardware encoding order, which differs from the stored-state listing.

## Stored state

The schema owns the public fields and validation rules used by construction,
snapshots, and `.machine` parsing. Registers and flags use uppercase names in
the formal language and lowercase fields in TypeScript. FLAGS is a group of
Boolean fields, not a second stored integer.

STOPPED and WAITING distinguish HLT from a WAIT instruction held by TEST.
INTRDEFERRED delays maskable recognition; RECOGNITIONDEFERRED inhibits all
recognition at a boundary; TRAPPENDING records an owed single-step trap.
These latches represent model bookkeeping, not extra architectural registers.
The caller supplies initial values; construction is separate from reset.

```cpu
cpu "8088" boundary segmented
state {
  register AX: 16
  register BX: 16
  register CX: 16
  register DX: 16
  register SP: 16
  register BP: 16
  register SI: 16
  register DI: 16
  register CS: 16
  register DS: 16
  register SS: 16
  register ES: 16
  register IP: 16
  latch STOPPED = halted
  latch WAITING = waiting
  latch INTRDEFERRED = interruptDeferred
  latch RECOGNITIONDEFERRED = recognitionDeferred
  latch TRAPPENDING = trapPending
  flag CF
  flag PF
  flag AF
  flag ZF
  flag SF
  flag TF
  flag IF
  flag DF
  flag OF
}
```

## Byte views and writes

Each read captures its stored word once. A write captures the **live** word
again at writeback, preserving its other half even if a fetch or flag update
has changed that word since the earlier operand read. Actions own their local
captures, so several byte writes can occur in one instruction without sharing
temporary values. Byte-operand definitions use these same views and actions.

```cpu
view AL "low byte of AX": 8 {
  word = register AX
  return lowByte(word)
}
action setAL "write AL, preserving its other half" (byte: 8) {
  preservedWord = register AX
  AX <- withBits(preservedWord, 7, 0, byte)
}
view CL "low byte of CX": 8 {
  word = register CX
  return lowByte(word)
}
action setCL "write CL, preserving its other half" (byte: 8) {
  preservedWord = register CX
  CX <- withBits(preservedWord, 7, 0, byte)
}
view DL "low byte of DX": 8 {
  word = register DX
  return lowByte(word)
}
action setDL "write DL, preserving its other half" (byte: 8) {
  preservedWord = register DX
  DX <- withBits(preservedWord, 7, 0, byte)
}
view BL "low byte of BX": 8 {
  word = register BX
  return lowByte(word)
}
action setBL "write BL, preserving its other half" (byte: 8) {
  preservedWord = register BX
  BX <- withBits(preservedWord, 7, 0, byte)
}
view AH "high byte of AX": 8 {
  word = register AX
  return highByte(word)
}
action setAH "write AH, preserving its other half" (byte: 8) {
  preservedWord = register AX
  AX <- withBits(preservedWord, 15, 8, byte)
}
view CH "high byte of CX": 8 {
  word = register CX
  return highByte(word)
}
action setCH "write CH, preserving its other half" (byte: 8) {
  preservedWord = register CX
  CX <- withBits(preservedWord, 15, 8, byte)
}
view DH "high byte of DX": 8 {
  word = register DX
  return highByte(word)
}
action setDH "write DH, preserving its other half" (byte: 8) {
  preservedWord = register DX
  DX <- withBits(preservedWord, 15, 8, byte)
}
view BH "high byte of BX": 8 {
  word = register BX
  return highByte(word)
}
action setBH "write BH, preserving its other half" (byte: 8) {
  preservedWord = register BX
  BX <- withBits(preservedWord, 15, 8, byte)
}
view PC "physical CS:IP": 32 {
  segment = register CS
  offset = register IP
  return and(add(shiftBits(extend(segment, 32), left, 4), extend(offset, 32)), u32($FFFFF))
}
```

The language uses a thirty-two-bit result for PC and explicitly masks it to
the twenty-bit bus. Stored CS and IP remain sixteen-bit values.

## FLAGS as a packed value

CF records carry or borrow, PF even parity of the low result byte, AF the
bit-3 carry or borrow, ZF zero, SF the result sign bit, and OF signed overflow.
TF requests single-stepping, IF permits maskable interrupts, and DF selects
the string-operation direction. An arithmetic instruction changes only the
flags specified by its policy; loading a register does not recompute flags.

The low byte is `SF ZF 0 AF 0 PF 1 CF`. The full original-chip FLAGS word
adds TF/IF/DF/OF in bits 8–11 and sets bits 12–15. Packing reads CF/PF/AF/ZF/SF,
then TF/IF/DF/OF for the word. Reserved bits are ignored on restoration.
SAHF updates five fields of the existing flags object. Full restoration
replaces all nine fields, and is shared by POPF and IRET. Their
interrupt-deferral and stack rules remain with those instructions.

```cpu
view LOWFLAGS "packed low FLAGS": 8 {
  cf = flag CF
  pf = flag PF
  af = flag AF
  zf = flag ZF
  sf = flag SF
  return pack<8>(sf, zf, 0, af, 0, pf, 1, cf)
}
policy RESTORELOWFLAGS "restore LOWFLAGS" (status: 8) {
  CF = bit(status, 0)
  PF = bit(status, 2)
  AF = bit(status, 4)
  ZF = bit(status, 6)
  SF = bit(status, 7)
}
view FLAGS "packed FLAGS word": 16 {
  cf = flag CF
  pf = flag PF
  af = flag AF
  zf = flag ZF
  sf = flag SF
  tf = flag TF
  if = flag IF
  df = flag DF
  of = flag OF
  return pack<16>(1, 1, 1, 1, of, df, if, tf, sf, zf, 0, af, 0, pf, 1, cf)
}
policy RESTOREFLAGS "restore FLAGS" (status: 16) {
  CF = bit(status, 0)
  PF = bit(status, 2)
  AF = bit(status, 4)
  ZF = bit(status, 6)
  SF = bit(status, 7)
  TF = bit(status, 8)
  IF = bit(status, 9)
  DF = bit(status, 10)
  OF = bit(status, 11)
}
action restoreFlags "replace all FLAGS" (status: 16) {
  replace RESTOREFLAGS(status)
}
```

`1001 111d` selects SAHF (`d=0`) or LAHF (`d=1`). SAHF captures AH before
updating CF/PF/AF/ZF/SF in layout order; OF/TF/IF/DF and all registers survive.
LAHF packs the low flags before writing AH, preserving live AL at writeback
and leaving all flags unchanged.

```cpu
family SAHF "1001 1110" {
  status = source AH
  apply RESTORELOWFLAGS(status)
}
family LAHF "1001 1111" {
  status = source LOWFLAGS
  perform setAH(status)
}
```

## Register selectors and immediate operands

The `rrr` field selects byte or word operands according to the instruction's
width bit. The common order is explicit in these catalogues; SP is not AH,
even though both occupy selector `100` in their respective widths.

```cpu
operands bytes {
  000 "AL" = view AL write setAL
  001 "CL" = view CL write setCL
  010 "DL" = view DL write setDL
  011 "BL" = view BL write setBL
  100 "AH" = view AH write setAH
  101 "CH" = view CH write setCH
  110 "DH" = view DH write setDH
  111 "BH" = view BH write setBH
}
operands words {
  000 "AX" = register AX
  001 "CX" = register CX
  010 "DX" = register DX
  011 "BX" = register BX
  100 "SP" = register SP
  101 "BP" = register BP
  110 "SI" = register SI
  111 "DI" = register DI
}
source immediateByte "immediate byte": 8 {
  byte = fetch
  return byte
}
source immediateWord "immediate word, low byte first": 16 {
  low = fetch
  high = fetch
  return concat(high, low)
}
```

## Immediate register loads

`1011 w rrr` selects MOV: `w=0` takes one immediate byte, `w=1` a low-first
word. Fetch the complete immediate before writing the destination. Byte
writes retain the current other half of the stored word. Preserve every
flag; a failed fetch leaves the destination untouched, while completed fetches
and IP advances remain.

```cpu
family MOVbyte "1011 0 rrr" for r in bytes named "MOV {r},n" {
  result = source immediateByte
  operand r <- result
}
family MOVword "1011 1 rrr" for r in words named "MOV {r},n" {
  result = source immediateWord
  operand r <- result
}
```

## Arithmetic and logic

ADD/ADC wrap a sum to the operand width; SUB/SBB/CMP wrap a difference.
ADC adds incoming CF and SBB subtracts it as a borrow. ADD, SUB, and CMP
ignore incoming CF. CMP sets subtraction flags without changing either operand.
Arithmetic sets CF for unsigned carry/borrow, AF for low-nibble carry/borrow,
OF for signed overflow, SF for the result's sign, and ZF for zero. PF uses
only the low result byte, even for word operations. INC/DEC set the same flags
as adding/subtracting one, but preserve CF. Every operation preserves TF/IF/DF.

OR/AND/XOR store their logical result. TEST sets flags from AND without writing
the result. Logic clears CF/OF and sets SF/ZF/PF from the result. Intel leaves
AF undefined; the model **clears AF deterministically**, matching the pinned
hardware fixtures rather than promising portable software behavior for that bit.
Byte operations preserve the other half of their stored word register.


NOT flips every bit within the operand width and preserves all flags. NEG
computes zero minus the operand: CF is set for every nonzero operand, OF
only for the most negative value (`80` or `8000`), and the other arithmetic
flags follow subtraction. INC/DEC memory forms share the register rules,
including preserving CF. Immediate TEST reads its operand without writing it;
NOT, NEG, INC, and DEC read then write, even when the value is unchanged.

## Arithmetic and logical flags

Addition and subtraction update CF, AF, OF, ZF, SF, and PF in that order.
CF describes unsigned overflow or borrow; OF describes signed overflow.
For example, byte `$7F + 1` produces `$80` with OF set and CF clear, while
`$FF + 1` produces zero with CF set and OF clear. Both cross a nibble boundary.
Word parity still considers only the low byte, unlike word zero and sign.

Logical operations clear OF, CF, and AF in that order, then set ZF/SF/PF.
Hardware leaves AF undefined for these operations; clearing it is this model's
deterministic choice. Every policy preserves TF/IF/DF. Right-hand expressions
use captured operands and are evaluated before the first flag write. These
policies serve the specification’s arithmetic and logical families, each retaining
its own operand decoding and effect order. A width parameter shares each policy
between byte and word operations. Parity always uses the low byte.

```cpu
policy ADDFLAGS<bits: 8, 16> "8088 ADD flags" (left: bits, right: bits, result: bits, incoming: flag) {
  CF = carry(left, right, incoming)
  AF = halfCarry(left, right, incoming)
  OF = addOverflow(left, right, incoming)
  ZF = zero(result)
  SF = negative(result)
  PF = evenParity(lowByte(result))
}
policy SUBFLAGS<bits: 8, 16> "8088 SUB flags" (left: bits, right: bits, result: bits, incoming: flag) {
  CF = borrow(left, right, incoming)
  AF = halfBorrow(left, right, incoming)
  OF = overflow(left, right, incoming)
  ZF = zero(result)
  SF = negative(result)
  PF = evenParity(lowByte(result))
}
policy LOGIC<bits: 8, 16> "8088 logical flags" (result: bits) {
  OF = 0
  CF = 0
  AF = 0
  ZF = zero(result)
  SF = negative(result)
  PF = evenParity(lowByte(result))
}
policy CARRY "restore captured carry" (incoming: flag) {
  CF = incoming
}
```

## Accumulator arithmetic and tests

The overall pattern is `00 ooo 10 w`: `ooo` selects the operation below,
while `w=0/1` selects AL/AX and an immediate byte/word. TEST instead uses
`1010 100 w`, applying AND's flags without replacing the accumulator.

| ooo | Operation | Incoming CF | Write result |
| --- | --- | --- | --- |
| 000 | ADD | Ignored | Yes |
| 001 | OR | Ignored | Yes |
| 010 | ADC | Added | Yes |
| 011 | SBB | Subtracted | Yes |
| 100 | AND | Ignored | Yes |
| 101 | SUB | Ignored | Yes |
| 110 | XOR | Ignored | Yes |
| 111 | CMP | Ignored | No |

Fetch the complete immediate low byte first, then read AL/AX. Only ADC and
SBB read incoming CF, after both operands. Apply flags before accumulator
writeback; byte writes preserve the live upper half of AX. CMP and TEST
never write or reread AX. Failed operand fetches prevent all body effects;
completed fetches and IP changes remain.

Do not read incoming flags. Set CF/AF/OF, then ZF/SF/PF from the wrapped result. Write AL/AX after flags and preserve TF/IF/DF.

## Word increment and decrement

`0100 d rrr` selects INC (`d=0`) or DEC (`d=1`) of a word register. Capture
the register, then CF. Add or subtract one with sixteen-bit wrapping, update
arithmetic flags, restore captured CF, and only then write the register.
Preserve TF/IF/DF. This deliberately retains the model's flag-write ordering,
including its transient CF update if a host observer interrupts execution.

```cpu
family INCword "0100 0 rrr" for r in words named "INC {r}" {
  left = operand r
  preservedCarry = flag CF
  right = u16(1)
  result = add(left, right)
  apply ADDFLAGS<16>(left, right, result, 0)
  apply CARRY(preservedCarry)
  operand r <- result
}
family DECword "0100 1 rrr" for r in words named "DEC {r}" {
  left = operand r
  preservedCarry = flag CF
  right = u16(1)
  result = subtract(left, right)
  apply SUBFLAGS<16>(left, right, result, 0)
  apply CARRY(preservedCarry)
  operand r <- result
}
```

## Logical and physical addresses

A logical address consists of a segment value and a 16-bit offset. Its physical
address is `(segment × 16 + offset) modulo 100000` in hexadecimal. Carries past
the 8088's twenty address lines are discarded. Different logical addresses can
refer to the same byte: `1000:2345` and `1234:0005` both address `12345`.

Instruction bytes are fetched through CS:IP. IP advances after each fetched
byte and wraps from `FFFF` to `0000`, leaving CS unchanged. Each new IP is
translated separately. For example, a fetch at `1234:FFFF` reads `2233F`, then
the next fetch reads `12340`. At `FFFF:000F`, consecutive fetches read `FFFFF`
and `00000` because the physical address itself wraps.

Direct memory MOV forms default to DS:offset; stack operations always use SS:SP. ModR/M
operands select DS or SS as described below. Words are low byte first. Each
byte's **offset wraps within its segment before translation** to a 20-bit
physical address. A word at `1234:FFFF` uses physical `2233F` and `12340`;
a word at `FFFF:000F` uses `FFFFF` and `00000`. Odd word addresses are valid.
Data transfers leave IP alone; instruction fetching advances it after each byte.

The hardware POP fixture at SS:FFFF and the hardware-test
author's word-bus routines supply the [boundary evidence](../../../../docs/cpus/8088/reference-notes.md#stack-and-control-flow-comparison).

RAM accesses and `instruction.address` contain physical addresses.
`record.before.cs` and `record.before.ip` retain the instruction's logical
address; `record.before.pc` equals `instruction.address`. The shared runner's
completion address is also physical. It stops at any CS:IP alias of that
address; it does not require a particular segment value.

## Segmented memory and ModR/M operands

ModR/M has the pattern **`mm ggg rrr`**. In register/memory ALU, MOV, TEST, and
XCHG, `ggg` selects a register. In immediate, unary, and shift groups it
selects the operation instead.
Register codes are AL/CL/DL/BL/AH/CH/DH/BH for bytes and
AX/CX/DX/BX/SP/BP/SI/DI for words. Register self-operations and byte halves
sharing a word use the operands' original values.

| `mm` | `rrr` interpretation | Displacement |
| --- | --- | --- |
| `00` | Memory base below, except `rrr=110` is direct DS:offset | None, or a word for the direct exception |
| `01` | Memory base below | Signed byte |
| `10` | Memory base below | Word, added modulo 65536 |
| `11` | Register selected by `rrr` | None |

| `rrr` | Memory base | Default segment |
| --- | --- | --- |
| `000` | BX+SI | DS |
| `001` | BX+DI | DS |
| `010` | BP+SI | SS |
| `011` | BP+DI | SS |
| `100` | SI | DS |
| `101` | DI | DS |
| `110` | BP (direct offset when `mm=00`) | SS (DS for the direct exception) |
| `111` | BX | DS |

Base and displacement are added modulo 65536 before segment translation.
The operand retains that segment and offset for its reads and writes; changing
a base register cannot change the already resolved address. For example,
`MOV BX,[BX+SI]` uses the original BX to find its source. Likewise,
`XCHG BX,[BX+SI]` reads and writes the address computed from the original BX.
XCHG reads both operands before writing either, including AL/AH exchanges
and self exchanges. `90` is the AX-with-AX encoding, also named NOP.
Memory exchanges record operand reads followed by writes; bus locking and
arbitration remain outside this instruction-level model.

The immediate group uses `1000 00 s w`. `80` is byte and `81` is word;
`82` is the documented alternate byte arithmetic encoding; `83` sign-extends
a byte to a word. `ggg=000/010/011/101/111` selects ADD/ADC/SBB/SUB/CMP
for every group byte. OR/AND/XOR (`001/100/110`) are documented only for
80/81; the 1979 manual marks those selectors unused for 82/83.
All documented register and memory choices are supported. Segment overrides
replace the default DS/SS choice for explicit memory operands.

LEA computes the effective offset without a data read. LES/LDS read the offset
word and segment word from the original resolved address before assigning either
destination; loading DS cannot redirect the second word. All four pointer-byte
offsets wrap inside that original segment. XLAT captures BX+AL modulo 65536,
reads one byte through DS or the override, and replaces only AL.

The declared execution boundary scans prefixes. It passes `overridden=0/1` and the
captured `segmentOverride` word to these families. Those are transient inputs,
not stored CPU fields. A segment prefix captures its register when encountered;
a later prefix replaces it. For ModR/M memory, capture the default segment and
base registers **before** fetching displacement bytes, even when overridden.
Absolute accumulator MOV instead fetches its offset before reading DS, and
never reads DS when an override supplies the segment.

A captured logical pointer concatenates segment and offset into thirty-two
bits. It is not a physical address. This preserves the offset boundary when a
word crosses `$FFFF`: wrap the second offset first, then project each byte
onto the twenty-bit bus. Sources take explicit numeric inputs, own their local
captures, and return one value. They do not retain a live address callback.

### Capturing the base and displacement

Each base source reads the default segment first, then the registers in the
order written in the table. The direct form captures DS before fetching the
low-first offset. The two catalogues make its `mm=00, rrr=110` exception explicit.

The zero pointer for a register form is unused. The original ModR/M byte still
determines whether an operand is a register or memory; no address is reserved
as a sentinel. Ordinary memory operands and ESC share `effectiveAddress`.
Failed displacement fetching retains completed fetches and prevents operand reads, flag changes, and destination writes.

### Reading and writing a captured pointer

`projectAddress(segment, offset, 4, 20)` expresses the physical projection:
shift the word segment by four, add the word offset, and keep twenty bits.
Word transfers read/write the low byte first. Each uses the captured pointer
for both bytes, regardless of changes during a memory callback.

```cpu
source memory8 "read a captured 8-bit memory operand" (pointer: 32): 8 {
  segment = bits(pointer, 31, 16)
  offset = truncate(pointer, 16)
  low = memory(projectAddress(segment, offset, 4, 20))
  return low
}
action store8 "write a captured 8-bit memory operand" (pointer: 32, contents: 8) using memory {
  segment = bits(pointer, 31, 16)
  offset = truncate(pointer, 16)
  memory(projectAddress(segment, offset, 4, 20)) <- contents
}
source memory16 "read a captured 16-bit memory operand" (pointer: 32): 16 {
  segment = bits(pointer, 31, 16)
  offset = truncate(pointer, 16)
  low = memory(projectAddress(segment, offset, 4, 20))
  high = memory(projectAddress(segment, add(offset, u16(1)), 4, 20))
  return concat(high, low)
}
action store16 "write a captured 16-bit memory operand" (pointer: 32, contents: 16) using memory {
  segment = bits(pointer, 31, 16)

  memory(projectAddress(segment, offset, 4, 20)) <- lowByte(contents)
  memory(projectAddress(segment, add(offset, u16(1)), 4, 20)) <- highByte(contents)
```

## Register/memory transfers

MOV reads only its source before writing its destination. XCHG reads the r/m
operand before the register, captures both originals, and writes r/m before
the register. This order also applies when two byte operands alias one word.
Each byte write preserves the live other half; memory words retain their
captured pointer throughout. Neither operation reads or changes flags.

```cpu
action move8 "move a resolved 8-bit operand" (destination: 8, source: 8, pointer: 32) using memory {
  contents = source readRM8(source, pointer)
  perform writeRM8(destination, pointer, contents)
}
action exchange8 "exchange resolved 8-bit operands" (left: 8, right: 8, pointer: 32) using memory {
  originalLeft = source readRM8(left, pointer)
  originalRight = source readRM8(right, pointer)
  perform writeRM8(left, pointer, originalRight)
  perform writeRM8(right, pointer, originalLeft)
}
action move16 "move a resolved 16-bit operand" (destination: 8, source: 8, pointer: 32) using memory {
  contents = source readRM16(source, pointer)
  perform writeRM16(destination, pointer, contents)
}

  originalLeft = source readRM16(left, pointer)
  originalRight = source readRM16(right, pointer)
```

`1000 10 d w` is MOV r/m,r or r,r/m. Fetch ModR/M and resolve its memory
operand before reading either value. `d=0` selects r/m as destination;

## Unary arithmetic, shifts, and products

Several instructions use ModR/M `mm ooo rrr`: `mm` and `rrr` choose the
operand, while `ooo` extends the primary opcode. Validate that extension
before displacement fetches or operand reads. Capture a memory pointer once;
all later reads and writes use it, even if a callback changes a segment.

### Increment, decrement, complement, and negation

INC and DEC preserve the incoming CF, captured after reading the operand.
NOT complements every bit without reading flags. NEG subtracts the operand
from zero, including the usual subtraction flags. For every width, flag
updates precede writeback; byte writes preserve the live other half.

### One bit at a time

The first byte is **`1101 00 v w`**: `v=0` uses count one, `v=1` uses CL;
`w=0/1` selects byte/word. ModR/M's operation field selects:

| `ggg` | Instruction | Direction | Bit inserted |
| --- | --- | --- | --- |
| `000` | ROL | Left | Outgoing high bit |
| `001` | ROR | Right | Outgoing low bit |
| `010` | RCL | Left | Previous CF |
| `011` | RCR | Right | Previous CF |
| `100` | SHL / SAL | Left | Zero; both mnemonics name the same encoding |
| `101` | SHR | Right | Zero |
| `110` | Unsupported | — | Undocumented encoding |
| `111` | SAR | Right | Sign bit |

The original 8088 uses **all eight bits of CL**, permitting 0–255 movements.
It does not apply the five-bit mask used by later x86 processors. Each movement
sets CF to the outgoing bit; carry rotations feed that flag into the next
movement. Counts equal to or larger than the width still execute. The count
is captured before changing any destination, including CL, CH, or CX.

For count one, OF records whether the sign bit changed. For larger counts
Intel leaves OF undefined; this model **preserves its incoming value**.
Rotations preserve SF/ZF/PF/AF. Nonzero shifts set SF/ZF/PF from the result
and **clear undefined AF deterministically**, as logical operations do.
Every form preserves TF/IF/DF. A zero count preserves all flags and the value.

Intel's [8086 Family User's Manual](https://www.ardent-tool.com/CPU/docs/Intel/808x/manuals/9800722-03_alt.pdf),
printed pages 2-39–2-40 and the instruction tables, defines these operations.
The [reference comparison](../../../../docs/cpus/8088/reference-notes.md#unary-shift-and-transfer-comparison)
checks documented encodings and defined flags against hardware cases.

Memory forms fetch the complete encoding, read the operand once, perform all
movements internally, then write it once. A zero count also records a read
and unchanged write. Word accesses retain the segment-offset wrapping policy.
These are explicit instruction-level access rules, without cycle counts or
prefetch effects. The specification describes each movement and its ordered flag updates.

```cpu
policy RESULT<bits: 8, 16> "zero, sign, and parity" (result: bits) {
  ZF = zero(result)
  SF = negative(result)
  PF = evenParity(lowByte(result))
}
policy SHIFT<bits: 8, 16> "shift result" (result: bits) {
  ZF = zero(result)
  SF = negative(result)
  PF = evenParity(lowByte(result))
  AF = 0
}
policy SHIFTOF<bits: 8, 16> "one-bit overflow" (before: bits, after: bits) {
  OF = negative(xor(before, after))
}

action shiftRM8 "shift or rotate a resolved 8-bit operand" (postbyte: 8, pointer: 32, count: 8, operation: 8) using memory {
  originalOperand = source readRM8(postbyte, pointer)
  shifted = iterate(count, originalOperand) {
    original = shifted
    result = match operation: 8 {
      case "00000000" {
        result = shiftLeft(original, negative(original))
        apply CARRY(negative(original))
        return result
      }
      case "00000001" {
        result = shiftRight(original, lowBit(original))
        apply CARRY(lowBit(original))
        return result
      }
      case "00000010" {
        incoming = flag CF
        result = shiftLeft(original, incoming)
        apply CARRY(negative(original))
        return result
      }
      case "00000011" {
        incoming = flag CF
        result = shiftRight(original, incoming)
        apply CARRY(lowBit(original))
        return result
      }
      case "00000100" {
        result = shiftLeft(original, 0)
        apply CARRY(negative(original))
        return result
      }
      case "00000101" {
        result = shiftRight(original, 0)
        apply CARRY(lowBit(original))
        return result
      }
      case "00000111" {
        result = shiftRight(original, negative(original))
        apply CARRY(lowBit(original))
        return result
      }
      otherwise unsupported
    }
    return result
  }
  when equal(count, u8(1)) {
    apply SHIFTOF<8>(originalOperand, shifted)
  }
  when and(not(lessThan(operation, u8(4), unsigned)), not(zero(count))) {
    apply SHIFT<8>(shifted)
  }
  perform writeRM8(postbyte, pointer, shifted)
}
```

### Multiply, divide, and the F6/F7 group

`1111 011 w` uses `/0` for immediate TEST, `/2` for NOT, `/3` for NEG,
and `/4`–`/7` for MUL, IMUL, DIV, IDIV. `/1` is undocumented. TEST fetches
its immediate before reading the operand and updates flags without writeback.

MUL/IMUL multiply AL by a byte into AX, or AX by a word into DX:AX. MUL sets
CF/OF when the upper half is nonzero; IMUL sets them when the result does not
fit the signed input width. SF/ZF/PF/AF are undefined and preserved. Operands
are read before assigning results, including aliases such as MUL AH or IMUL DX.

DIV divides unsigned AX by a byte, placing quotient/remainder in AL/AH, or
unsigned DX:AX by a word, placing them in AX/DX. IDIV uses signed values,
truncates toward zero, and gives the remainder the dividend's sign. Arithmetic
flags are undefined and preserved; successful division preserves control flags. On the original 8088 the signed quotient ranges
are **−127..127 and −32767..32767**: even −128 and −32768 cause divide errors.
These limits follow the 1979 manual and pinned hardware fixtures.

A zero divisor or out-of-range quotient delivers interrupt type 0 after fetching
the instruction and reading the divisor, leaving AX/DX unchanged. The frame
saves the **following IP**, as on the original 8088, rather than the faulting
instruction's address used by later x86. Arithmetic flags remain unchanged under
the model's undefined-flag policy; entry saves them and clears IF/TF.


### Decimal digits and sign extension

DAA/DAS (`0010 s111`) adjust packed decimal digits after addition/subtraction;
AAA/AAS (`0011 s111`) adjust unpacked digits. Read AL first, then AH for
unpacked adjustments. The low-digit decision consults AF only if the nibble
is below ten. For packed adjustment, read AF again for the high threshold:
original AL above `$9F` when AF is set, otherwise above `$99`. Only a value
below that threshold needs a CF read. These are ordered decisions, not
unconditional reads of all flags.

Packed correction sets AF then CF, writes AL preserving live AH, then sets
ZF/SF/PF. Unpacked correction adjusts the captured AH and AL independently,
masks AL to four bits, writes AX, then CF and AF. Undefined flags stay intact.

DAA/DAS adjust AL after packed-decimal addition/subtraction. Low-digit
correction uses AF or a low nibble above nine; high correction uses CF or
original AL above `99` when incoming AF is clear, **`9F` when it is set**.
CF records that high correction; DAS does not add a separate low-digit borrow.
AF records low correction, SF/ZF/PF describe adjusted AL, and undefined OF is
preserved. AH is unchanged. These original-chip details differ from later x86:
DAA with AL=`9E`, AF=1, CF=0 gives `A4`, CF=0; DAS with AL=0, AF=1, CF=0 gives
`FA`, CF=0. Valid packed-BCD arithmetic is checked independently in decimal.

AAA/AAS adjust unpacked AL and AH independently, then mask AL to its low nibble.
A carry/borrow from AL's byte adjustment does not adjust AH a second time.
AF/CF report adjustment; undefined OF/SF/ZF/PF are preserved. AAM splits AL into
decimal quotient AH and remainder AL; AAD combines AH×10+AL into AL modulo 256
and clears AH. Only the documented fixed second byte `0A` is supported.
AAM/AAD set SF/ZF/PF from AL and preserve undefined CF/AF/OF. CBW and CWD
sign-extend the accumulator without changing flags.

```cpu
source decimalLow "low digit needs correction" (original: 8): flag {
  aboveNine: flag = not(lessThan(and(original, u8($0F)), u8(10), unsigned))
  decision = choose aboveNine : flag {
    then {
      return 1
    }
    else {
      incoming = flag AF
      return incoming
    }
  }
  return decision
}
source decimalHigh "high digit needs correction" (original: 8): flag {
  auxiliary = flag AF
  aboveLimit: flag = not(lessThan(original, select(auxiliary, u8($A0), u8($9A)), unsigned))
  decision = choose aboveLimit : flag {
    then {
      return 1
    }
    else {
      incoming = flag CF
      return incoming
    }
  }
  return decision
}

  CF = high
}
```

## Indirect control and the FE/FF groups

`1111 111 w` selects INC `/0` and DEC `/1`. Only the word group `$FF`
also allows near CALL `/2`, far CALL `/3`, near JMP `/4`, far JMP `/5`,
and PUSH `/6`. `/7` and register encodings of far pointers are rejected before
address resolution. A far pointer is offset then segment, each low byte first;
wrap the logical offset between words before projecting it to the bus.

Capture targets before stack writes. A near CALL then captures and pushes IP;
a far CALL captures and pushes CS, then captures live IP and pushes it. Commit
the new CS before IP only after the whole frame succeeds. PUSH SP on the
original 8088 captures SP minus two as its source, before the stack action's
independent update of live SP. All paths preserve flags except INC/DEC.

The stack action decrements live SP before reading SS and the new SP, then
writes low byte before high byte. A failed write retains completed effects.
This same action serves near/far calls and indirect PUSH.

```cpu
action pushWord "push a captured word" (word: 16) using memory {
  pointer = register SP
  SP <- subtract(pointer, u16(2))
  segment = register SS
  offset = register SP
  perform store16(concat(segment, offset), word)
}

source farPointer "read offset then segment from a captured pointer" (pointer: 32): 32 {
  targetOffset = source memory16(pointer)

}

}
```

## Control flow and stack

Near jumps and calls preserve CS. Short JMP and
Jcc add a signed byte to IP after the operand; near JMP/CALL add a signed word.
The resulting IP wraps to 16 bits. Jcc always fetches its displacement,
including when untaken. No transfer reads or prefetches its target.

| Opcodes | Condition for first mnemonic | First / inverted mnemonic (aliases) |
| --- | --- | --- |
| `70` / `71` | OF | JO / JNO |
| `72` / `73` | CF | JB (JC/JNAE) / JAE (JNC/JNB) |
| `74` / `75` | ZF | JE (JZ) / JNE (JNZ) |
| `76` / `77` | CF or ZF | JBE (JNA) / JA (JNBE) |
| `78` / `79` | SF | JS / JNS |
| `7A` / `7B` | PF | JP (JPE) / JNP (JPO) |
| `7C` / `7D` | SF differs from OF | JL (JNGE) / JGE (JNL) |
| `7E` / `7F` | ZF or SF differs from OF | JLE (JNG) / JG (JNLE) |

PUSH decrements SP by two, wrapping to 16 bits, then writes the selected word
low byte first at SS:SP and SS:(SP+1). **PUSH SP stores the decremented SP** on
the original 8088. POP reads those bytes, increments SP by two, then assigns
the word to its destination. **POP SP ends with the popped value**, replacing
the increment. All register stack forms preserve every flag. Segment PUSH/POP use the original
SS for the entire access, including POP SS. POP r/m resolves its destination
before the pop; an SP register destination receives the popped word after
the increment. FF /6 PUSH SP has the same decremented-value rule as opcode 54.

CALL fetches the complete displacement before pushing the following IP,
including when the stack overlaps the fetched encoding. It then branches from
that following IP. RET reads IP from the stack without further adjustment to
that returned address; `RET n` subsequently adds its unsigned immediate byte
count to SP, with 16-bit wrapping. The count may be odd or zero. Discarded
parameters cause no reads. Near calls and returns preserve CS; every call and return preserves flags.
Indirect near CALL/JMP read a register or memory target before writing the
stack or changing IP. Far immediate and memory forms capture a complete
segment:offset pointer; memory forms require a memory ModR/M choice. A far
CALL pushes the old CS then the following IP before replacing CS:IP, even
when stack writes overlap the pointer or instruction. RETF pops IP then CS,
then optionally adds its unsigned parameter byte count to SP.

LOOPNE/LOOPE/LOOP decrement CX modulo 65536 before testing for nonzero. The
first two also require ZF clear/set; JCXZ tests original CX for zero and
preserves it. Each fetches its signed displacement on either path. All preserve
flags and CS; no branch fetches its target as part of the same step.

The [control-flow example](../../../../docs/cpus/8088/examples/control-flow.md) saves an AX loop counter
while two nested calls accumulate a sum in RAM, then restores the counter and
compares it before branching. IP, SP, and the physical PC stay distinct.

## Conditional branches and loops

A relative displacement is added to the post-fetch IP, wrapping within CS.
Every conditional branch fetches its displacement before testing flags, and
only a taken branch reads or writes IP. `0111 ttt p` selects one of eight
positive tests with `ttt`; `p=1` inverts that test.

| ttt | p=0 | p=1 | Positive test |
| --- | --- | --- | --- |
| 000 | JO | JNO | OF |
| 001 | JB | JAE | CF |
| 010 | JE | JNE | ZF |
| 011 | JBE | JA | CF or ZF |
| 100 | JS | JNS | SF |
| 101 | JP | JNP | PF |
| 110 | JL | JGE | SF differs from OF |
| 111 | JLE | JG | ZF or (SF differs from OF) |

Compound conditions short-circuit: JBE/JA read CF before ZF, and JLE/JG read
ZF before SF and OF. The source returns a Boolean decision; the low polarity
bit inverts it without rereading any flag.

```cpu
source branchDecision "ordered branch test" (condition: 8): flag {
  positive = match shiftBits(condition, right, 1): flag {
    case "00000000" {
      test = flag OF
      return test
    }
    case "00000001" {
      test = flag CF
      return test
    }
    case "00000010" {
      test = flag ZF
      return test
    }
    case "00000011" {
      first = flag CF
      result = choose first : flag {
        then {
          return 1
        }
        else {
          second = flag ZF
          return second
        }
      }
      return result
    }
    case "00000100" {
      test = flag SF
      return test
    }
    case "00000101" {
      test = flag PF
      return test
    }
    case "00000110" {
      sign = flag SF
      overflow = flag OF
      return xor(sign, overflow)
    }
    case "00000111" {
      first = flag ZF
      result = choose first : flag {
        then {
          return 1
        }
        else {
          sign = flag SF
          overflow = flag OF
          return xor(sign, overflow)
        }
      }
      return result
    }
    otherwise unsupported
  }
  return xor(positive, lowBit(condition))
}
action relativeJump "branch from live post-fetch IP" (offset: 16) {
  position = register IP
  IP <- add(position, offset)
}

  1010 "JP" = 10
```

## Direct stacks, calls, and returns

The existing `pushWord` action owns all word pushes, including native interrupt
frames. A pop captures SS:SP before reading the low/high bytes, then reads and
increments live SP only after both reads succeed. POP SP subsequently replaces
that incremented pointer with the captured word. Memory POP captures its
destination before reading the stack and never reads the destination itself.

`0101 p rrr` selects register PUSH/POP. Original 8088 PUSH SP differs from
other registers: its source is the captured SP minus two, before the stack's
independent pointer update. The separate source makes that exception visible;
all other encoded registers use the ordinary register catalogue.

```cpu
source popWord "pop segmented word": 16 {
  segment = register SS
  offset = register SP
  word = source memory16(concat(segment, offset))
  pointer = register SP
  SP <- add(pointer, u16(2))
  return word
}
source pushedSP "original 8088 PUSH SP source": 16 {
  pointer = register SP
  return subtract(pointer, u16(2))
}

  original = operand r
  perform pushWord(original)
}
family pushSP "0101 0100" named "PUSH SP" {
  original = source pushedSP
  perform pushWord(original)
}

}
```

failure leaves it uncommitted. The same rule applies to MOV into a segment.

PUSHF (`1001 1100`) captures the packed FLAGS word before pushing. POPF
(`1001 1101`) reads the complete word before consulting live IF. A transition
from clear IF to set IF requests INTR deferral before replacing the flag
object. Reserved bits are ignored by the specification's existing restore policy.
IRET uses this same specification action after completing its far return.

```cpu
family pushFlags "1001 1100" named "PUSHF" {

  perform pushWord(original)
}

  status = source popWord
  oldIF = flag IF
  when not(oldIF) {
    when bit(status, 9) {
```

## Halt and pending traps

HLT advances IP and sets `halted`. With no owed trap it returns `outcome: "halted"`; later steps return the same outcome, `instruction: null`, and no
accesses or changes. Reset or accepted INTR/NMI releases halt. When TF was
sampled for HLT, the instruction instead reports `executed` with `halted` and
`trapPending` set. The next step delivers the trap and releases halt, so a
bounded runner can continue into the trap handler. Restored snapshots preserve
both the halt state and any pending trap.

## Simple controls

HLT sets the stored stopped latch; the boundary still owns retirement and
pending traps. CMC complements live CF. CLC/STC and CLD/STD set their selected
flag without reading it. CLI clears IF directly; STI reads IF, requests INTR
deferral only when it was clear, then sets it. None of these bodies commits
recognition latches itself. These requests remain explicit instruction effects.

## Port input and output

The eight forms share **`1110 r 1 d w`**: `r=0` fetches an immediate byte port,
`r=1` uses all of DX, `d=0/1` selects input/output, and `w=0/1` selects AL/AX.
The immediate is zero-extended to a 16-bit port address. Port space is separate
from RAM and unsegmented; no segment register contributes to a port address.
See Intel's [manual](https://www.ardent-tool.com/CPU/docs/Intel/808x/manuals/9800722-03_alt.pdf),
sections 2.4 and 2.7, I/O addressing on page 2-72, and table 4-13.

Byte IN replaces AL while preserving AH. Word IN reads low then high bytes
and replaces AX after both reads succeed. OUT captures AL or AX before calling
the device. Word transfers always call the device twice, at the selected port
and `(port + 1) modulo 10000` in hexadecimal. Thus immediate port `FF` continues
at `0100`, and DX=`FFFF` continues at `0000`. Odd word ports are valid. This is
the 8088's byte bus behavior, with [hardware comparison evidence](../../../../docs/cpus/8088/reference-notes.md#port-input-and-output-comparison).
All flags and other registers, including DX, are preserved.

Instruction fetching still advances and wraps CS:IP before any port transfer.
Segment overrides do not affect port selection. LOCK retains the model's lack
of bus-arbitration effects. REP/REPNE remain unsupported for IN/OUT: rejection
occurs at the opcode, before an immediate port or device callback is read.
Each complete IN/OUT is one step; the runner cannot pause between its two bytes.

An absent device fails only when a port instruction reaches its transfer.
Input values must be integers in 0–255; malformed values throw `RangeError`
without coercion. Callback failures propagate without a step record or rollback:
fetched IP and completed device effects remain. A failed word IN leaves all of
AX unchanged; a failed second output leaves the first output delivered. These
are host-failure policies, not hardware exceptions or resumable bus cycles.

RAM and device callbacks may inspect snapshots but cannot recursively call
`step()`, `reset()`, or `interrupt()` on the same CPU. The shared execution guard clears after
success or failure. Reset, inspection, and already halted steps never call the
port connection. Reset preserves the connection and external device state.

Byte input replaces AL while preserving AH as observed after the callback.

```cpu
source immediatePort "zero-extended immediate port": 16 {
  byte = fetch
  return extend(byte, 16)
}
source dxPort "DX port": 16 {
  selector = register DX
  return selector
}
```

accesses keep partial word failures and device ordering visible.

## String elements and repetition

`1010 ooo w` selects MOVS (`ooo=010`), CMPS (`011`), STOS (`101`),
LODS (`110`), or SCAS (`111`); `w=0/1` means byte/word. Each instruction
invocation handles **one element**, preserving an interrupt boundary between
repeated elements. The prefix scanner supplies `repeatMode=0` for no repeat,
`1` for F3 (REP/REPE), and `2` for F2 (REPNE), plus the original prefix-start
IP and a captured segment override. REPNE is supported only for CMPS/SCAS.

`26/2E/36/3E` override the data segment with ES/CS/SS/DS. They apply to explicit
memory operands, absolute MOV, XLAT, and string sources. They never redirect
instruction fetches, implicit stack accesses, or string destinations in ES.
`F0` (LOCK) is consumed with its instruction; bus arbitration has no modeled
state or effect with one CPU and flat RAM. Memory XCHG has the same limitation.

Prefix state belongs to the current attempt and is included in fetched bytes.
The last segment prefix and last repeat prefix win independently. A prefix-only
64 KiB code segment rejects after one full scan, preserving state and RAM;
there is no later-x86 fifteen-byte instruction limit.

MOVS copies DS:SI to ES:DI; CMPS subtracts ES:DI from DS:SI; STOS stores AL/AX
at ES:DI; LODS loads AL/AX from DS:SI; SCAS subtracts ES:DI from AL/AX. CMPS/SCAS
set subtraction flags without writing either operand. The other string operations
preserve flags. Used indices advance by one/two bytes with DF clear or retreat
with DF set, wrapping to 16 bits; unprefixed strings preserve CX.

`F3` repeats MOVS/STOS/LODS while CX is nonzero and repeats CMPS/SCAS while
CX is nonzero and the new ZF is set. `F2` repeats CMPS/SCAS while CX is nonzero
and the new ZF is clear. REPNE on other strings and REP on non-string instructions
are undocumented and rejected. Incoming ZF does not prevent the first comparison.
A zero starting CX completes after instruction fetches, without data accesses,
index changes, or flag changes.

**One repeated element is one step.** After an element, decrement CX; if another
is required, restore IP to the first prefix. The next step refetches the complete
encoding. The final element leaves IP after the instruction. This makes the
runner's step budget meaningful and allows snapshot restoration without hidden
iteration state. RAM edits between steps affect the next fetch and operand;
self-modifying REP therefore follows this explicit instruction-level policy,
without hardware prefetch-queue behavior.

Nonempty operations capture source segment/SI and fixed destination ES/DI before any data access,
even if the selected operation uses only one side. This retains the declared
model's observable access schedule. Word reads/writes use the same low-first,
offset-wrapping memory rules as other instructions.

After data and comparison flags, read live DF to select the signed byte/word

refetches prefixes, so code changes, snapshot resumption, and interrupt offers
remain observable. The finishing action's numeric selectors describe which
indices and repeat condition the calling family uses.

```cpu
action finishString "advance live indices and decide repetition" (width: 8, useSI: 8, useDI: 8, compares: 8, repeatMode: 8, startIP: 16) {

    DI <- add(position, delta)

    }
  }
}
```

## Interrupt instructions and shared entry

All sources use the same four-byte vector in physical memory at `vector × 4`:
little-endian IP followed by CS. Entry reads all four bytes **before any stack
write**, so a stack overlapping the vector table cannot redirect the current
entry. It captures FLAGS, clears IF/TF, and pushes FLAGS, CS, then return IP
through SS:SP. Each push decrements SP by two and writes low byte first, with
the ordinary segment-offset wrapping rule. The final stack therefore contains
IP at SP, CS at SP+2, and FLAGS at SP+4. Entry does not fetch handler code.

INT3 selects type 3; INT n fetches its type byte; INTO selects type 4 only when
OF is set. Untaken INTO performs only its instruction fetch. These software
entries and divide errors are not blocked by IF or recognition delays.
IRET pops IP, CS, then FLAGS, restoring all nine flag bits and ignoring reserved
bits. It uses the same word-pop and flag-restoration helpers as RETF and POPF.

The vector-first order follows the original interrupt microcode described in
[Ken Shirriff's silicon analysis](https://www.righto.com/2023/02/8086-interrupt.html)
and is checked against the [hardware fixtures](../../../../docs/cpus/8088/reference-notes.md#interrupt-comparison).

The formal entry action clears TF then IF and the recognition/wait/halt
latches. It pushes FLAGS, live CS, and live IP, then commits target CS and IP
after the complete frame succeeds. Software forms use `1100 11 tt`:
INT3 (`tt=00`), INT with a fetched type byte (`01`), INTO (`10`), and IRET (`11`).
`report interrupt` records completed software delivery; it performs no vector
or stack effects itself.

```cpu
policy ENTRYFLAGS "disable traps and mask INTR" () {
  TF = 0
  IF = 0
}
action enterInterrupt "interrupt entry" (vector: 8) using memory {
  offset = shiftBits(extend(vector, 16), left, 2)
  targetIP = source memory16(concat(u16(0), offset))
  targetCS = source memory16(concat(u16(0), add(offset, u16(2))))
  savedFlags = source FLAGS
  apply ENTRYFLAGS()
  RECOGNITIONDEFERRED <- 0
  INTRDEFERRED <- 0
  WAITING <- 0
  STOPPED <- 0
  perform pushWord(savedFlags)
  savedCS = register CS
  perform pushWord(savedCS)
  savedIP = register IP
  perform pushWord(savedIP)
  CS <- targetCS
  IP <- targetIP
}
family INT3 "1100 1100" named "INT3" {
  perform enterInterrupt(u8(3))
  report interrupt(u8(3))
}
family INT "1100 1101" named "INT n" {
  vector = fetch
  perform enterInterrupt(vector)
  report interrupt(vector)
}
family INTO "1100 1110" named "INTO" {
  overflow = flag OF
  when overflow {
    perform enterInterrupt(u8(4))
    report interrupt(u8(4))
  }
}
family IRET "1100 1111" named "IRET" {
  perform returnFar(u16(0))
  perform restoreStackFlags()
}
```

IRET completes the ordinary far return before the separate FLAGS pop. Failed
FLAGS reads retain restored IP/CS and completed SP changes. The shared FLAGS
action requests INTR delay on a zero-to-one IF transition before replacing
flags. The specification retirement policy samples the instruction's original
TF, so restoring flags cannot retroactively create or cancel that owed trap.

## External interrupt delivery

`interrupt("intr", acknowledge)` offers a currently asserted INTR request;
`interrupt("nmi")` offers an NMI edge selected by the caller. Neither queues a
request. The caller retains asserted INTR and latched NMI requests, offers NMI
first when both are pending, and reoffers a deferred request at a later boundary.
IF masks INTR only. `interruptDeferred` delays INTR; `recognitionDeferred` delays
both sources. Ignored offers do not acknowledge, access memory, or release halt/wait.

Accepted INTR releases halt/wait and calls `acknowledge()` once for an integer type
byte in 0–255. This callback abstracts the whole hardware acknowledgement
sequence, including its two INTA bus cycles; only the supplied byte is recorded.
NMI uses type 2 without a callback. Both enter through the current CS:IP, which
already points after HLT, to the first prefix of an unfinished REP, or to an
in-progress WAIT opcode.

`Cpu8088InterruptRecord` has detached `before`/`after` snapshots, `source`,
`instruction: null`, and ordered `accesses`. An accepted record adds
`outcome: "accepted"` and `vector`; an ignored record adds `outcome: "ignored"`
and `reason: "masked" | "deferred"`. Deferral takes precedence when both apply.
INTR's `{ kind: "acknowledge", value }` precedes vector reads and frame writes.
The callback is required for an eligible INTR offer and its byte is validated
before any vector access. The API does not model a PIC, pin timing, or an
interrupt scheduler.

## Recognition delays and single stepping

CLI clears IF. STI sets IF and, when it changes from zero to one, inhibits INTR
through the following retired instruction. POPF and IRET apply the same delay
when restoring IF from zero to one. Another STI with IF already set consumes
an existing delay without renewing it. NMI and traps do not use this IF delay.

On the original chip, MOV/POP into **any** segment register delays recognition
of INTR, NMI, and traps through the following instruction. This includes ES
and DS, not only SS; consecutive such loads renew `recognitionDeferred`. LES/LDS
and control-flow changes to CS do not set it. A retired instruction, REP element, or successful WAIT
sample consumes a delay. TEST release renews the delay for all sources. Unsupported encodings and failed ordinary instructions do
not consume it; partially completed entry follows the failure policy below. Prefixes never form separate retirement boundaries.

TF is sampled before execution. An instruction/REP element or WAIT sample with it set
leaves `trapPending`; the next `step()` delivers type 1 before fetching another
instruction, unless segment inhibition requires another instruction first.
Thus POPF/IRET setting TF begins trapping after the following instruction;
clearing TF does not cancel the trap owed for the instruction that cleared it.
An owed trap survives higher-priority software, divide-error, or external entry
and is delivered before that handler's first instruction. Callers offer pending
NMI/INTR before `step()` to preserve their priority over a pending trap.

Each REP element is a boundary in this model. Interruption saves the first
prefix's address while repetition is unfinished; IRET resumes with the remaining
CX and advanced indices. This retains the existing complete-prefix refetch
policy. It does not emulate the original chip's multiple-prefix restart quirks
or prefetch-dependent self-modification.

## Interrupt connection failures

RAM and acknowledgement callbacks may inspect state, but reentrant mutating
calls throw before changing it. Callback errors propagate without a record or
rollback. A failing acknowledgement leaves an accepted INTR's halt/wait release in
place, with no vector read. A failing vector read preserves CS:IP and SP;
IF/TF clear only after the entire vector is read. A failing frame write leaves
that flag clearing, each attempted push's SP decrement, and completed writes
in place; the target CS:IP commits after all three pushes succeed.

IRET commits each completed pop's SP increment, changes CS:IP after both return
words, then restores FLAGS after its complete word is read. A pending trap is
consumed when its delivery begins, including on failure. These rules expose
host failures; they do not model bus faults, cycle-level register timing, or
resumption halfway through an instruction. Reset always clears all recognition
latches without reading RAM or calling a device.

## WAIT and coprocessor escape

ESC has the pattern **`1101 1ooo` + `mm ppp rrr`**. Concatenate `ooo:ppp` to
obtain the external opcode (0–63). The remaining ModR/M bits select a source
using ordinary segment defaults, overrides, displacements, and offset wrapping.
Register forms make no data access and expose no CPU register value. Memory
forms always read a word, low byte first, including external operations that
will eventually write memory. The CPU itself discards that word and changes no
registers or flags except advancing IP and the ordinary recognition latches.

After the read, an attached `escape(request)` receives a `Cpu8088Escape`:

- `opcode`: the decoded six-bit external opcode.
- `modRM`: the complete second byte, preserving the external processor's selectors.
- `memory`: `null` for a register form, or `{ segment, offset, address, value }`
  for a memory form. `address` is the first byte's physical address and `value`
  is the word read by the CPU.

The callback receives a detached request. The step then records
`{ kind: "escape", ...request }` with its own copy, after instruction and data
reads. With no callback, ESC still performs the dummy word read and records
the event. An external processor owns any further reads, writes, computation,
and busy state; those operations are not invented CPU accesses. This interface
represents execution of ESC, not instruction-queue snooping or bus arbitration.
A complete 8087 implementation is not required.

WAIT calls `test()` once per step and records `{ kind: "test", high }`.
The Boolean represents the physical pin: **high waits, low continues**.
A machine without a busy device can explicitly connect `test: () => false`.
There is no default pin level; a missing TEST connection throws when WAIT is
actually sampled. The arithmetic TEST instruction is unrelated.

On a high sample, `waiting` becomes true and IP identifies the WAIT opcode,
including after segment/LOCK prefixes and across IP wrapping. The first step
retains the fetched bytes and reports `waiting`. Later steps sample TEST without
fetching RAM; they report `instruction: null`. A low sample clears `waiting`,
advances IP past WAIT, and reports `executed`; a continuation also carries
`continuation: "wait"`. No following instruction is executed in that same step.
The shared runner stops on `waiting` and can resume when the machine changes TEST.
A saved waiting snapshot needs no hidden prefix or continuation object. RAM
edits do not replace an in-progress WAIT; interrupt return refetches current RAM.

Each busy sample consumes prior recognition delays and permits INTR/NMI or a
single-step trap at the next boundary. IF still masks INTR. An accepted entry
clears `waiting` and saves the WAIT opcode's IP, so IRET refetches it. Prefixes
are not restored: they have no operand effect on WAIT. An ignored request leaves
waiting state untouched. As with REP, a sample with incoming TF set owes a trap;
a busy WAIT with an owed trap reports `executed` so the runner can reach that
entry instead of stopping. An already owed eligible trap is delivered before
sampling TEST again.

A **low TEST sample inhibits all recognition through the following instruction**,
including when WAIT never had to pause. It sets `recognitionDeferred`, the same
latch used by segment loads. TF can still owe a trap; delivery waits until the
following instruction (normally ESC) retires. Consecutive ready WAIT instructions
renew the delay. These rules follow the [manual and microcode comparison](../../../../docs/cpus/8088/reference-notes.md#esc-and-wait-comparison).
The step boundary abstracts wait-test cycles; pin synchronization, clock counts,
the interrupted WAIT's hardware refetch before vectoring, and prefetch are not modeled.

Missing/malformed TEST callbacks and thrown device errors propagate without a
record. TEST must return a Boolean without coercion. Initial instruction fetches
remain reflected in IP; a failed continuation leaves its waiting state and IP
unchanged. No recognition latch changes until the sample succeeds. If an ESC
operand read fails, no external request is issued. If the ESC callback fails,
completed reads, fetched IP, and device effects remain; no rollback is attempted.
Callbacks preserve their receiver and may inspect snapshots but cannot reenter
`step`, `reset`, or `interrupt`. Reset clears waiting and recognition state while
preserving connections and devices; it neither samples TEST nor issues ESC.

```cpu
action pollWait "sample TEST for initial WAIT or continuation" (resuming: 8) using boundary {
  high = sample test
  WAITING <- high
  when zero(resuming) {
    when high {
      position = register IP
      IP <- subtract(position, u16(1))
    }
  }
  when not(zero(resuming)) {
    when not(high) {
      position = register IP
      IP <- add(position, u16(1))
    }
  }
  when not(high) {
    defer all
  }
}
family WAIT "1001 1011" named "WAIT" {
  perform pollWait(u8(0))
}
```

ESC uses `1101 1 ooo` and ModR/M `mm ppp rrr`; `ooo:ppp` forms the
six-bit coprocessor opcode. Register forms send the selector without reading
CPU registers. Memory forms resolve the ordinary segmented address and read
a complete dummy word even if no coprocessor is connected. Only then do they
send the captured segment, offset, physical address, and word. The device
adapter detaches requests and records only successful delivery. ESC itself
leaves CPU state and flags unchanged; no coprocessor arithmetic is emulated.

```cpu
codes escapes: 8 {
  000 "0" = 0
  001 "1" = 1
  010 "2" = 2
  011 "3" = 3
  100 "4" = 4
  101 "5" = 5
  110 "6" = 6
  111 "7" = 7
}
action escapeMemory "capture dummy word before ESC delivery" (opcode: 8, postbyte: 8, pointer: 32) using memory, boundary {
  segment = bits(pointer, 31, 16)
  offset = truncate(pointer, 16)
  contents = source memory16(pointer)
  send escape(opcode, postbyte) with memory(segment, offset, projectAddress(segment, offset, 4, 20), contents)
}
family ESC (overridden: 8, segmentOverride: 16) "1101 1 ooo" for o in escapes named "ESC {o}" {
  postbyte = fetch
  highOpcode = operand o
  opcode = or(shiftBits(highOpcode, left, 3), extend(bits(postbyte, 5, 3), 8))
  match postbyte {
    case "11 xxx xxx" {
      send escape(opcode, postbyte)
    }
    case "0x xxx xxx" {
      pointer = source effectiveAddress(postbyte, overridden, segmentOverride)
      perform escapeMemory(opcode, postbyte, pointer)
    }
    case "10 xxx xxx" {
      pointer = source effectiveAddress(postbyte, overridden, segmentOverride)
      perform escapeMemory(opcode, postbyte, pointer)
    }
    otherwise unsupported
  }
}
```

## Reset and execution lifecycle

Reset selects CS:IP=`FFFF:0000`, clears DS/SS/ES, all nine flags, halt/wait,
and the three recognition latches. It reads no vector: physical `$FFFF0` is
the next instruction address. General registers and RAM are preserved because
Intel leaves those register reset values unspecified. This is a deterministic
model policy, not a claim about their power-on values.

```cpu
policy RESETFLAGS "clear every modeled flag" () {
  CF = 0
  PF = 0
  AF = 0
  ZF = 0
  SF = 0
  TF = 0
  IF = 0
  DF = 0
  OF = 0
}
action resetState "reset control state, preserving general registers and RAM" {
  CS <- u16($FFFF)
  IP <- u16(0)
  WAITING <- 0
  STOPPED <- 0
  TRAPPENDING <- 0
  RECOGNITIONDEFERRED <- 0
  INTRDEFERRED <- 0
  ES <- u16(0)
  SS <- u16(0)
  DS <- u16(0)
  replace RESETFLAGS()
}
action setIP "replace the logical instruction offset" (offset: 16) {
  IP <- offset
}
action advanceIP "advance the live offset after one successful fetch" {
  offset = register IP
  IP <- add(offset, u16(1))
}
action beginTrap "consume an owed trap before attempting entry" {
  TRAPPENDING <- 0
}
action retireInstruction "commit requested delays and the original trap sample" (intr: flag, all: flag, sampledTF: flag, owedTrap: flag) {
  INTRDEFERRED <- intr
  RECOGNITIONDEFERRED <- all
  TRAPPENDING <- or(owedTrap, sampledTF)
}
```

Each successful instruction-byte read advances **live IP**, including prefix
and operand bytes. The offset wraps without carrying into CS. A failed read
does not advance it. The separately declared PC view labels the instruction
record; fetching projects live CS:IP onto the twenty-bit bus.

The segment prefixes have encoding `001 ss 110`, where `ss=00/01/10/11`
selects ES/CS/SS/DS. Each captures the selected segment's value when consumed;
a later override replaces that capture. F2/F3 similarly replace the repeat
mode. LOCK is consumed without bus-arbitration effects. Prefixes belong to
one attempt, never retire separately, and are bounded by one full code segment
rather than a later-x86 instruction-length limit. Repeat prefixes admit only
families with repeat inputs; those families check the mode and execute at most
one element, rewinding to `startIP` when another element remains.

An owed trap runs before halt or WAIT unless recognition is inhibited. Its
latch clears **before** vector reads, even if entry fails. Otherwise a halted
step has no accesses; a waiting step calls `pollWait(1)` without fetching.
Ordinary attempts and successful WAIT samples capture TF and the owed-trap
latch before effects, then commit requested INTR/all delays and those samples
at retirement. POPF/IRET cannot retroactively change the sampled TF. Busy WAIT
and HLT report `executed` when a trap is owed, allowing a runner to reach its
entry. A released WAIT reports a continuation with no instruction bytes.

Unsupported encodings restore the original IP and skip retirement; failed
host callbacks retain completed effects and propagate without a record.
A divide error enters type 0 from the **following** IP, as on the original
8088, then retires with the original trap sample. Software entry reports its
own vector after its explicit effects. Neither kind cancels an owed trap.
External INTR/NMI offers share the same reentrancy guard. Their ordered gates
below preserve deferral-before-masking and reject without acknowledgement or
wake-up. Eligible INTR validates callback presence before releasing WAIT/HLT,
then obtains its vector. Both sources use the specification's shared entry action.

```cpu
action acceptInterrupt "release WAIT and HLT before acknowledgement or entry" {
  WAITING <- 0
  STOPPED <- 0
}

execution segmented {
  memory 20
  counter IP write setIP
  segment CS shift 4
  record address PC
  fetch action advanceIP
  prefixes limit 65536 {
    segment $26 ES
    segment $2E CS
    segment $36 SS
    segment $3E DS
    ignore $F0
    repeat $F2 2
    repeat $F3 1
  }
  stopped STOPPED
  waiting WAITING with pollWait(1)
  pending "trap" vector 1 when TRAPPENDING unless RECOGNITIONDEFERRED with beginTrap then enterInterrupt
  fault "divide-error" vector 0 with enterInterrupt
  reset action resetState
  retire action retireInstruction sampling flag TF, latch TRAPPENDING
  unsupported restore counter
  failure retain
  interrupt offers {
    source intr acknowledge {
      unless latch RECOGNITIONDEFERRED otherwise "deferred"
      unless latch INTRDEFERRED otherwise "deferred"
      when flag IF otherwise "masked"
      accept action acceptInterrupt
      enter action enterInterrupt
    }
    source nmi vector 2 {
      unless latch RECOGNITIONDEFERRED otherwise "deferred"
      accept action acceptInterrupt
      enter action enterInterrupt
    }
  }
}
```

## Public interface

The generated class accepts RAM, complete initial state, and optional machine-owned
port, TEST, and ESC connections. Snapshot byte registers and the physical PC are
views over copied state. Restoring a snapshot recreates every CPU-owned boundary
latch; the machine restores its memory and device state separately.

```cpu
interface Cpu8088 "Instruction-level Intel 8088 with flat 1 MiB RAM and segmented addresses." {
  snapshot al = AL
  snapshot ah = AH
  snapshot bl = BL
  snapshot bh = BH
  snapshot cl = CL
  snapshot ch = CH
  snapshot dl = DL
  snapshot dh = DH
  snapshot pc = PC
}
```

## Stored state and derived views

`Cpu8088State` contains stored fields only. `.machine` definitions conventionally
use uppercase register/flag names and camelCase control latches. Snapshots add
AL/AH, BL/BH, CL/CH, DL/DH, and physical `pc`; these cannot be assigned in a
`.machine` definition. There is no public packed FLAGS field or prefetch queue.
Pending external requests and NMI edge detection belong to the caller.

## Construction and inspection

`new Cpu8088(ram, initialState, connections?)` requires exactly 1 MiB RAM. It copies and
validates every declared register and flag. Each field is read once, including
non-enumerable getters; extra metadata and derived views are ignored. Invalid
numeric state or RAM size throws `RangeError`; non-Boolean flags or control latches throw
`TypeError`. Construction performs neither reset nor RAM/device accesses.

The optional `Cpu8088Connections` object provides `ports`, `escape`, and `test`.
`ports` is a [`BytePorts`](../port-access.ts) connection
with `readPort(port)` and `writePort(port, value)`: 16-bit addresses and one byte
per callback. `escape(request)` receives decoded external instructions;
`test()` samples the physical TEST level. Each connection is independent.
Devices own their state; a reconstructed CPU must reconnect separately restored
devices. `snapshot()` returns detached state and views without accessing RAM. Its
TypeScript type is recursively readonly. Bypassing that typing cannot change
the CPU, another snapshot, or a retained execution record. A snapshot may
initialize a new CPU; its views are recomputed from its stored registers.
The CPU retains no execution history.

## Instruction steps

`step()` delivers an owed trap, samples an already waiting TEST input, or
attempts one instruction/REP element.
A fetched instruction returns a `Cpu8088StepRecord` with
independent before/after snapshots, the instruction's physical start address
and fetched bytes, ordered `Cpu8088Access` entries, and an outcome. Memory
`read`/`write` entries contain physical `address` and `value`; port
`input`/`output` entries contain `port` and `value`. ESC adds a decoded
`escape` event; WAIT adds a `test` sample. All share one log in transfer order.
`Cpu8088MemoryAccess` remains the memory-only alias. Software and divide-error
entry attach `interrupt: { source, vector }` to the triggering instruction's
executed record. An owed single-step trap instead returns `instruction: null`,
`outcome: "executed"`, and `interrupt: { source: "trap", vector: 1 }`; its step
contains vector/frame accesses and no instruction fetch. External offers have
their own records, described below.

Lengths follow the encoding: opcode, optional ModR/M and displacement, then
any immediate. **All instruction bytes are fetched before data accesses**;
data bytes do not appear in `instruction.bytes`. Word reads and writes are low
byte first. MOV reads only its source and writes only its destination. ALU
operations read the original operands before writing a result; CMP and TEST
perform no destination write. Writes are recorded even when values are unchanged.
If a write overlaps code, it cannot alter the already fetched instruction;
later steps read current RAM while retained records keep their earlier bytes.

## Unsupported instructions

Unsupported first bytes produce `outcome: "unsupported"`, `reason: "opcode"`
after their opcode fetch (and any preceding prefixes). Invalid ModR/M operation
or register selections reject immediately after ModR/M, before displacements,
immediates, or operand accesses. AAM/AAD reject after their second byte when it
is not `0A`. Invalid repetition combinations reject at the opcode.
All preserve complete state and RAM; repeating an attempt repeats its reads.
This atomic rejection is a model policy, not an illegal-instruction exception
implemented by the original chip. Divide errors use the declared entry action as described above.

All documented opcode forms are implemented. External computation and TEST
levels use the connections above; unsupported encodings remain outside the
documented instruction inventory.

## CPU reset

`reset()` returns detached
before/after snapshots and an empty access list, without a step outcome or
instruction. A later step fetches current RAM at `FFFF0`. Reset does not restore
an example's memory image; creating a fresh example performs that restart.
