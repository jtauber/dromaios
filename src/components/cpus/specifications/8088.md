# Intel 8088

This chapter begins the executable guide to Dromaios's original Intel 8088.
It owns stored state, byte-register views and writes, packed FLAGS, and the
instruction families defined below. The remaining instruction definitions,
decoder, reset, and execution boundary still live in TypeScript. Their
[model contract](../../../../docs/cpus/8088/model.md) remains authoritative
until those parts migrate; the [coverage report](../../../../docs/cpus/coverage.md#8088)
measures that work separately from instruction support.

## Historical background

Intel introduced the 8088 in 1979, following the 8086 in 1978. It retains the
8086's sixteen-bit programmer's architecture while using an eight-bit external
data bus. IBM chose the 8088 for the IBM PC, introduced in August 1981.
Intel's [processor chronology][chronology] and [account of the IBM PC][history]
provide the historical context; its [family manual][manual] describes the
architecture and instruction encodings used here.

That eight-bit bus does not make AX an eight-bit register. A word calculation
still operates on sixteen bits; transferring a word to memory takes two byte
transfers. The physical processor separates instruction execution from bus
activity and uses a four-byte instruction queue. Dromaios models ordered
instruction effects, without a prefetch queue or clock timing. Its recorded
accesses therefore describe the emulator's observations, not a cycle trace.

## The programmer's machine

| Registers | Role |
| --- | --- |
| AX, BX, CX, DX | Word registers with independently addressable low/high bytes |
| SP, BP, SI, DI | Word registers used for stacks, addressing, and string operations |
| CS, DS, SS, ES | Segment registers supplying the base of a 64 KiB address window |
| IP | Offset of the next instruction within CS |
| FLAGS | Arithmetic results and the TF/IF/DF control flags |

AL and AH are views of AX's low and high bytes. If AX is `$1234`, AL is `$34`
and AH is `$12`. Writing `$56` to AL gives AX=`$1256`; there is no separate
AL value to synchronize. The same relationship holds for BX, CX, and DX.
SP, BP, SI, and DI do not have separately addressable byte halves on this chip.

A memory address combines a segment and offset: shift the segment left four
bits, add the sixteen-bit offset, and keep the low twenty bits. Thus
`1234:0010` and `1235:0000` both select physical `$12350`. At the top of the
address space, `FFFF:0010` wraps to zero. IP wraps within its segment;
advancing it does not carry into CS. The snapshot's `pc` is a derived physical
CS:IP view, while instruction fetching still belongs to the native decoder.

Immediate words and memory words are little-endian: `MOV AX,1234H` is encoded
`$B8 $34 $12`. Here `$` introduces hexadecimal, while binary opcode patterns
run from most to least significant bit. Register selectors follow the
hardware encoding order, which differs from the stored-state listing.

## Stored state

The schema owns the public fields and validation rules used by construction,
snapshots, and `.machine` parsing. Registers and flags use uppercase names in
the formal language and lowercase fields in TypeScript. FLAGS is a group of
Boolean fields, not a second stored integer.

STOPPED and WAITING distinguish HLT from a WAIT instruction held by TEST.
INTRDEFERRED delays maskable recognition; RECOGNITIONDEFERRED inhibits all
recognition at a boundary; TRAPPENDING records an owed single-step trap.
These latches represent model bookkeeping, not extra architectural registers.
The caller supplies initial values; construction is separate from reset.

```cpu
cpu "8088"
state {
  register AX: 16
  register BX: 16
  register CX: 16
  register DX: 16
  register SP: 16
  register BP: 16
  register SI: 16
  register DI: 16
  register CS: 16
  register DS: 16
  register SS: 16
  register ES: 16
  register IP: 16
  latch STOPPED = halted
  latch WAITING = waiting
  latch INTRDEFERRED = interruptDeferred
  latch RECOGNITIONDEFERRED = recognitionDeferred
  latch TRAPPENDING = trapPending
  flag CF
  flag PF
  flag AF
  flag ZF
  flag SF
  flag TF
  flag IF
  flag DF
  flag OF
}
```

## Byte views and writes

Each read captures its stored word once. A write captures the **live** word
again at writeback, preserving its other half even if a fetch or flag update
has changed that word since the earlier operand read. Actions own their local
captures, so several byte writes can occur in one instruction without sharing
temporary values. Native instruction definitions use these same chapter views
and actions while their bodies await migration.

```cpu
view AL "low byte of AX": 8 {
  word = register AX
  return lowByte(word)
}
action setAL "write AL, preserving its other half" (byte: 8) {
  preservedWord = register AX
  AX <- concat(highByte(preservedWord), byte)
}
view CL "low byte of CX": 8 {
  word = register CX
  return lowByte(word)
}
action setCL "write CL, preserving its other half" (byte: 8) {
  preservedWord = register CX
  CX <- concat(highByte(preservedWord), byte)
}
view DL "low byte of DX": 8 {
  word = register DX
  return lowByte(word)
}
action setDL "write DL, preserving its other half" (byte: 8) {
  preservedWord = register DX
  DX <- concat(highByte(preservedWord), byte)
}
view BL "low byte of BX": 8 {
  word = register BX
  return lowByte(word)
}
action setBL "write BL, preserving its other half" (byte: 8) {
  preservedWord = register BX
  BX <- concat(highByte(preservedWord), byte)
}
view AH "high byte of AX": 8 {
  word = register AX
  return highByte(word)
}
action setAH "write AH, preserving its other half" (byte: 8) {
  preservedWord = register AX
  AX <- concat(byte, lowByte(preservedWord))
}
view CH "high byte of CX": 8 {
  word = register CX
  return highByte(word)
}
action setCH "write CH, preserving its other half" (byte: 8) {
  preservedWord = register CX
  CX <- concat(byte, lowByte(preservedWord))
}
view DH "high byte of DX": 8 {
  word = register DX
  return highByte(word)
}
action setDH "write DH, preserving its other half" (byte: 8) {
  preservedWord = register DX
  DX <- concat(byte, lowByte(preservedWord))
}
view BH "high byte of BX": 8 {
  word = register BX
  return highByte(word)
}
action setBH "write BH, preserving its other half" (byte: 8) {
  preservedWord = register BX
  BX <- concat(byte, lowByte(preservedWord))
}
view PC "physical CS:IP": 32 {
  segment = register CS
  offset = register IP
  return and(add(shiftBits(extend(segment, 32), left, 4), extend(offset, 32)), u32($FFFFF))
}
```

The language uses a thirty-two-bit result for PC and explicitly masks it to
the twenty-bit bus. Stored CS and IP remain sixteen-bit values.

## FLAGS as a packed value

CF records carry or borrow, PF even parity of the low result byte, AF the
bit-3 carry or borrow, ZF zero, SF the result sign bit, and OF signed overflow.
TF requests single-stepping, IF permits maskable interrupts, and DF selects
the string-operation direction. An arithmetic instruction changes only the
flags specified by its policy; loading a register does not recompute flags.

The low byte is `SF ZF 0 AF 0 PF 1 CF`. The full original-chip FLAGS word
adds TF/IF/DF/OF in bits 8–11 and sets bits 12–15. Packing reads CF/PF/AF/ZF/SF,
then TF/IF/DF/OF for the word. Reserved bits are ignored on restoration.
SAHF updates five fields of the existing flags object. Full restoration
replaces all nine fields, and is shared by native POPF and IRET. Their
interrupt-deferral and stack rules remain with those instructions.

```cpu
view LOWFLAGS "packed low FLAGS": 8 {
  cf = flag CF
  pf = flag PF
  af = flag AF
  zf = flag ZF
  sf = flag SF
  cfBit = select(cf, u8($01), u8(0))
  pfBit = select(pf, u8($04), u8(0))
  afBit = select(af, u8($10), u8(0))
  zfBit = select(zf, u8($40), u8(0))
  sfBit = select(sf, u8($80), u8(0))
  return or(or(or(or(or(u8($02), cfBit), pfBit), afBit), zfBit), sfBit)
}
policy RESTORELOWFLAGS "restore LOWFLAGS" (status: 8) {
  CF = not(zero(and(status, u8($01))))
  PF = not(zero(and(status, u8($04))))
  AF = not(zero(and(status, u8($10))))
  ZF = not(zero(and(status, u8($40))))
  SF = not(zero(and(status, u8($80))))
}
view FLAGS "packed FLAGS word": 16 {
  cf = flag CF
  pf = flag PF
  af = flag AF
  zf = flag ZF
  sf = flag SF
  tf = flag TF
  if = flag IF
  df = flag DF
  of = flag OF
  cfBit = select(cf, u16($0001), u16(0))
  pfBit = select(pf, u16($0004), u16(0))
  afBit = select(af, u16($0010), u16(0))
  zfBit = select(zf, u16($0040), u16(0))
  sfBit = select(sf, u16($0080), u16(0))
  tfBit = select(tf, u16($0100), u16(0))
  ifBit = select(if, u16($0200), u16(0))
  dfBit = select(df, u16($0400), u16(0))
  ofBit = select(of, u16($0800), u16(0))
  arithmetic = or(cfBit, or(pfBit, or(afBit, or(zfBit, sfBit))))
  controls = or(tfBit, or(ifBit, or(dfBit, ofBit)))
  return or(u16($F002), or(arithmetic, controls))
}
policy RESTOREFLAGS "restore FLAGS" (status: 16) {
  CF = not(zero(and(status, u16($0001))))
  PF = not(zero(and(status, u16($0004))))
  AF = not(zero(and(status, u16($0010))))
  ZF = not(zero(and(status, u16($0040))))
  SF = not(zero(and(status, u16($0080))))
  TF = not(zero(and(status, u16($0100))))
  IF = not(zero(and(status, u16($0200))))
  DF = not(zero(and(status, u16($0400))))
  OF = not(zero(and(status, u16($0800))))
}
action restoreFlags "replace all FLAGS" (status: 16) {
  replace RESTOREFLAGS(status)
}
```

`1001 111d` selects SAHF (`d=0`) or LAHF (`d=1`). SAHF captures AH before
updating CF/PF/AF/ZF/SF in layout order; OF/TF/IF/DF and all registers survive.
LAHF packs the low flags before writing AH, preserving live AL at writeback
and leaving all flags unchanged.

```cpu
family SAHF "1001 1110" {
  status = source AH
  apply RESTORELOWFLAGS(status)
}
family LAHF "1001 1111" {
  status = source LOWFLAGS
  perform setAH(status)
}
```

## Register selectors and immediate operands

The `rrr` field selects byte or word operands according to the instruction's
width bit. The common order is explicit in these catalogues; SP is not AH,
even though both occupy selector `100` in their respective widths.

```cpu
operands bytes {
  000 "AL" = view AL write setAL
  001 "CL" = view CL write setCL
  010 "DL" = view DL write setDL
  011 "BL" = view BL write setBL
  100 "AH" = view AH write setAH
  101 "CH" = view CH write setCH
  110 "DH" = view DH write setDH
  111 "BH" = view BH write setBH
}
operands words {
  000 "AX" = register AX
  001 "CX" = register CX
  010 "DX" = register DX
  011 "BX" = register BX
  100 "SP" = register SP
  101 "BP" = register BP
  110 "SI" = register SI
  111 "DI" = register DI
}
source immediateByte "immediate byte": 8 {
  byte = fetch
  return byte
}
source immediateWord "immediate word, low byte first": 16 {
  low = fetch
  high = fetch
  return concat(high, low)
}
```

## Immediate register loads

`1011 w rrr` selects MOV: `w=0` takes one immediate byte, `w=1` a low-first
word. Fetch the complete immediate before writing the destination. Byte
writes retain the current other half of the stored word. Preserve every
flag; a failed fetch leaves the destination untouched, while completed fetches
and IP advances remain.

```cpu
family MOVbyte "1011 0 rrr" for r in bytes named "MOV {r},n" {
  result = source immediateByte
  operand r <- result
}
family MOVword "1011 1 rrr" for r in words named "MOV {r},n" {
  result = source immediateWord
  operand r <- result
}
```

## Arithmetic and logical flags

Addition and subtraction update CF, AF, OF, ZF, SF, and PF in that order.
CF describes unsigned overflow or borrow; OF describes signed overflow.
For example, byte `$7F + 1` produces `$80` with OF set and CF clear, while
`$FF + 1` produces zero with CF set and OF clear. Both cross a nibble boundary.
Word parity still considers only the low byte, unlike word zero and sign.

Logical operations clear OF, CF, and AF in that order, then set ZF/SF/PF.
Hardware leaves AF undefined for these operations; clearing it is this model's
deterministic choice. Every policy preserves TF/IF/DF. Right-hand expressions
use captured operands and are evaluated before the first flag write. These
policies also serve the remaining native arithmetic and logical bodies; their
operand decoding and sequencing still belong to those definitions.

```cpu
policy ADD8FLAGS "8088 ADD flags" (left: 8, right: 8, result: 8, incoming: flag) {
  CF = carry(left, right, incoming)
  AF = halfCarry(left, right, incoming)
  OF = addOverflow(left, right, incoming)
  ZF = zero(result)
  SF = negative(result)
  PF = evenParity(result)
}
policy SUB8FLAGS "8088 SUB flags" (left: 8, right: 8, result: 8, incoming: flag) {
  CF = borrow(left, right, incoming)
  AF = halfBorrow(left, right, incoming)
  OF = overflow(left, right, incoming)
  ZF = zero(result)
  SF = negative(result)
  PF = evenParity(result)
}
policy LOGIC8 "8088 logical flags" (result: 8) {
  OF = 0
  CF = 0
  AF = 0
  ZF = zero(result)
  SF = negative(result)
  PF = evenParity(result)
}
policy ADD16FLAGS "8088 ADD flags" (left: 16, right: 16, result: 16, incoming: flag) {
  CF = carry(left, right, incoming)
  AF = halfCarry(left, right, incoming)
  OF = addOverflow(left, right, incoming)
  ZF = zero(result)
  SF = negative(result)
  PF = evenParity(lowByte(result))
}
policy SUB16FLAGS "8088 SUB flags" (left: 16, right: 16, result: 16, incoming: flag) {
  CF = borrow(left, right, incoming)
  AF = halfBorrow(left, right, incoming)
  OF = overflow(left, right, incoming)
  ZF = zero(result)
  SF = negative(result)
  PF = evenParity(lowByte(result))
}
policy LOGIC16 "8088 logical flags" (result: 16) {
  OF = 0
  CF = 0
  AF = 0
  ZF = zero(result)
  SF = negative(result)
  PF = evenParity(lowByte(result))
}
policy CARRY "restore captured carry" (incoming: flag) {
  CF = incoming
}
```

## Accumulator arithmetic and tests

The overall pattern is `00 ooo 10 w`: `ooo` selects the operation below,
while `w=0/1` selects AL/AX and an immediate byte/word. TEST instead uses
`1010 100 w`, applying AND's flags without replacing the accumulator.

| ooo | Operation | Incoming CF | Write result |
| --- | --- | --- | --- |
| 000 | ADD | Ignored | Yes |
| 001 | OR | Ignored | Yes |
| 010 | ADC | Added | Yes |
| 011 | SBB | Subtracted | Yes |
| 100 | AND | Ignored | Yes |
| 101 | SUB | Ignored | Yes |
| 110 | XOR | Ignored | Yes |
| 111 | CMP | Ignored | No |

Fetch the complete immediate low byte first, then read AL/AX. Only ADC and
SBB read incoming CF, after both operands. Apply flags before accumulator
writeback; byte writes preserve the live upper half of AX. CMP and TEST
never write or reread AX. Failed operand fetches prevent all body effects;
completed fetches and IP changes remain.

### ADD

Do not read incoming flags. Set CF/AF/OF, then ZF/SF/PF from the wrapped result. Write AL/AX after flags and preserve TF/IF/DF.

```cpu
family ADD8 "00 000 10 0" named "ADD AL,n" {
  right = source immediateByte
  left = source AL
  result = add(left, right)
  apply ADD8FLAGS(left, right, result, 0)
  perform setAL(result)
}
family ADD16 "00 000 10 1" named "ADD AX,n" {
  right = source immediateWord
  left = register AX
  result = add(left, right)
  apply ADD16FLAGS(left, right, result, 0)
  AX <- result
}
```

## Word increment and decrement

`0100 d rrr` selects INC (`d=0`) or DEC (`d=1`) of a word register. Capture
the register, then CF. Add or subtract one with sixteen-bit wrapping, update
arithmetic flags, restore captured CF, and only then write the register.
Preserve TF/IF/DF. This deliberately retains the model's flag-write ordering,
including its transient CF update if a host observer interrupts execution.

```cpu
family INCword "0100 0 rrr" for r in words named "INC {r}" {
  left = operand r
  preservedCarry = flag CF
  right = u16(1)
  result = add(left, right)
  apply ADD16FLAGS(left, right, result, 0)
  apply CARRY(preservedCarry)
  operand r <- result
}
family DECword "0100 1 rrr" for r in words named "DEC {r}" {
  left = operand r
  preservedCarry = flag CF
  right = u16(1)
  result = subtract(left, right)
  apply SUB16FLAGS(left, right, result, 0)
  apply CARRY(preservedCarry)
  operand r <- result
}
```

snapshots, fetch/access order, wrapping, arithmetic flags, and failure retention.
The [register semantics tests](../../../../tests/components/cpus/semantics/8088-registers.test.ts)

observable effect of the register families. The
[chapter checks](../../../../tests/components/cpus/semantics/literate-8088.test.ts)

[integration test](../../../../tests/scripts/8088-chapter-integration.test.ts)

snapshots, instruction execution, and machine parsing.

The next migration must extend this executable explanation to effective
addresses and ModR/M operands, remaining instruction families, then reset,
execution boundaries, and the public interface. None of those portions is
implicitly implemented by the prose here. The existing
[model contract](../../../../docs/cpus/8088/model.md) records their behavior
and limitations, including prefix handling, interrupts, WAIT, and ESC.
