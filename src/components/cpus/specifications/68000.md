# Motorola 68000

The 68000 presents eight 32-bit data registers and eight address-register
names. Byte, word, and long operations share those registers; a 16-bit operation
word selects their size and addressing modes. The active stack pointer is A7,
backed by separate user and supervisor storage. Logical addresses retain 32
bits while the physical address bus exposes 24.

This chapter owns stored state, derived register and status views, register-only
MOVE/MOVEA, MOVEQ, EXT, SWAP, EXG, and the initial indirect MOVE.W forms.
The remaining instruction families, effective-address decoding, exception
entry, reset, and retirement still use TypeScript definitions and the native
core. The [model contract](../../../../docs/cpus/68000/model.md) describes those
boundaries and links the hardware references; the
[language guide](../../../../docs/cpus/literate-specifications.md) explains the notation.

## Stored state

D0–D7 and A0–A6 are independent 32-bit registers. USP and SSP store the two
stack pointers; there is no additional stored A7. PC retains its full logical
address, IR the current operation word, and the interrupt mask three bits.
The entry group records exception-frame bookkeeping, separate from architectural
flags. HALTED, FAULTED, and TRACEPENDING support the execution boundary.

```cpu
cpu "68000"
state {
  register D0: 32
  register D1: 32
  register D2: 32
  register D3: 32
  register D4: 32
  register D5: 32
  register D6: 32
  register D7: 32
  register A0: 32
  register A1: 32
  register A2: 32
  register A3: 32
  register A4: 32
  register A5: 32
  register A6: 32
  register USP: 32
  register SSP: 32
  register PC: 32
  register IR: 16
  register INTERRUPTMASK: 3 = interruptMask
  latch HALTED
  latch FAULTED
  latch TRACEPENDING = tracePending
  group ENTRY {
    choice KIND: "none", "reset", "fault", "exception", "trap"
    register VECTOR: 8
  }
  flag X
  flag N
  flag Z
  flag V
  flag C
  flag T
  flag S
}
```

## Construction and inspection

`new Cpu68000(memory, initialState, connections?)` requires a 16 MiB address
space and all these stored fields:

| Fields | Constraint |
| --- | --- |
| `d0`–`d7` | Unsigned 32-bit data registers |
| `a0`–`a6` | Unsigned 32-bit address registers |
| `usp`, `ssp` | Unsigned 32-bit user and supervisor stack pointers |
| `pc` | Unsigned 32-bit program counter |
| `ir` | Unsigned 16-bit last completely fetched operation word |
| `interruptMask` | Integer from 0 through 7 |
| `halted` | Boolean STOP latch; required in initial state |
| `faulted` | Boolean terminal double-fault latch; only external reset releases it |
| `tracePending` | Boolean owed-trace latch; required independently of T and STOP |
| `entry.kind` | `none`, `reset`, `fault`, `exception`, or `trap`: phase awaiting its first opcode fetch |
| `entry.vector` | Unsigned byte identifying that exception vector; ignored for `none` and `reset` |
| `flags.x/n/z/v/c` | Boolean extend, negative, zero, overflow, and carry |
| `flags.t/s` | Boolean trace and supervisor bits |

The original status register has X/N/Z/V/C at bits 4–0, interrupt mask at
10–8, S at 13, and T at 15. There is no master-mode bit or second trace bit.
Instructions pack and unpack SR/CCR from these fields; snapshots keep no duplicate
packed register. STOP sets `halted`; completed instructions that began with T
set owe a trace through `tracePending`. All three latches are stored in snapshots. `faulted` takes priority over STOP,
trace, and interrupt recognition. `ir` changes as soon as both opcode bytes
have been read; extension fetches, trace, and interrupt entry preserve it.
An odd instruction PC therefore stacks the supplied or previously fetched IR.
Synchronous exceptions and trace ignore the interrupt mask; external requests
use the level rules below. Entry clears T and selects SSP.

The exported `cpu68000StateDescription` is generated from the state block above.
It supplies field names and constraints to construction and machine parsing.
Construction reads each declared field once, validates it, and owns a copy.
Numeric and named-choice errors throw `RangeError`; missing or invalid flag groups and Boolean
fields throw `TypeError`. Extra metadata and derived views are ignored.
Construction does not read RAM, reset, or execute.

`snapshot()` owns a detached copy with readonly TypeScript types. It adds:

- `a7`: `ssp` when S is set, otherwise `usp`. The active pointer is a view,
  so switching modes cannot leave a duplicate A7 value out of sync.
- `physicalPc`: the low 24 bits of `pc`.

Snapshots can initialize another CPU. Neither inspection nor snapshot copying
accesses RAM. Mutating caller state or an earlier snapshot cannot alter the CPU.

`entry` preserves the context of the next initial opcode fetch across snapshots.
Ordinary initial state uses `{ kind: "none", vector: 0 }`. Successful reset
sets `reset`; bus/address-error entry sets `fault`; group-1 exceptions, trace,
and interrupts set `exception`; group-2 instruction traps set `trap`.
The vector distinguishes, for example, TRAP #0 from TRAP #1. A complete opcode
fetch clears the context to `none`, vector 0; a partial fetch preserves it.
This records entry sequencing without storing a prefetch queue. The existing
trace/interrupt boundary priority still applies before that fetch.

## A7 and physical addresses

S selects the stack bank at each operand's turn: clear means USP, set means
SSP. Reading A7 reads only that selected register. Capturing the choice separately
lets an exchange resolve both register identities before reading either value,
and retain those identities through writeback. The bank view returns zero for
user storage and one for supervisor storage.

```cpu
view STACKBANK "active stack bank" : 8 {
  supervisor = flag S
  return select(supervisor, u8(1), u8(0))
}
view A7 "active stack pointer" : 32 {
  bank = source STACKBANK
  pointer = choose not(zero(bank)) : 32 {
    then {
      stack = register SSP
      return stack
    }
    else {
      stack = register USP
      return stack
    }
  }
  return pointer
}
view PHYSICALPC "physical program address" : 32 {
  logical = register PC
  return and(logical, u32($FFFFFF))
}
```

The three-bit address code names A0–A7. Selecting A7 captures its current bank;
internal codes seven and eight then identify USP and SSP respectively. This
selection reads S only for A7 and does not read either stack pointer yet.

```cpu
codes addressRegisters {
  000 "A0"
  001 "A1"
  010 "A2"
  011 "A3"
  100 "A4"
  101 "A5"
  110 "A6"
  111 "A7"
}
source selectAddressRegister "select address-register storage" (code: 3) : 8 {
  selected = choose zero(xor(code, u3(7))) : 8 {
    then {
      bank = source STACKBANK
      return add(u8(7), bank)
    }
    else {
      return extend(code, 8)
    }
  }
  return selected
}
operands addressStorage {
  000 "A0" = register A0
  001 "A1" = register A1
  010 "A2" = register A2
  011 "A3" = register A3
  100 "A4" = register A4
  101 "A5" = register A5
  110 "A6" = register A6
  111 "USP" = register USP
}
source readAddressRegister "read selected address register" (selected: 8) : 32 {
  contents = match selected : 32 {
    case "00000rrr" for r in addressStorage {
      original = operand r
      return original
    }
    case "00001000" {
      original = register SSP
      return original
    }
    otherwise unsupported
  }
  return contents
}
action writeAddressRegister "write selected address register" (selected: 8, contents: 32) {
  match selected {
    case "00000rrr" for r in addressStorage {
      operand r <- contents
    }
    case "00001000" {
      SSP <- contents
    }
    otherwise unsupported
  }
}
```

## Condition codes and status

CCR packs X, N, Z, V, C into bits 4 through 0. SR additionally holds T in bit
15, S in bit 13, and the interrupt mask in bits 10–8; reserved bits read as zero.
Capture SR in the established order: T, S, interrupt mask, then X/N/Z/V/C.
CCR writes update those five flags in place. Full SR writes then update T/S
and finally the interrupt mask, preserving the existing flag object.

```cpu
view CCR "condition code register" : 16 {
  x = flag X
  n = flag N
  z = flag Z
  v = flag V
  c = flag C
  return or(or(or(or(or(u16(0), select(x, u16($10), u16(0))), select(n, u16($8), u16(0))), select(z, u16($4), u16(0))), select(v, u16($2), u16(0))), select(c, u16($1), u16(0)))
}
view SR "status register" : 16 {
  trace = flag T
  supervisor = flag S
  mask = register INTERRUPTMASK
  condition = source CCR
  return or(or(or(select(trace, u16($8000), u16(0)), select(supervisor, u16($2000), u16(0))), shiftBits(extend(mask, 16), left, 8)), condition)
}
policy conditionCode "restore condition codes" (contents: 16) {
  X = not(zero(and(contents, u16($10))))
  N = not(zero(and(contents, u16($8))))
  Z = not(zero(and(contents, u16($4))))
  V = not(zero(and(contents, u16($2))))
  C = not(zero(and(contents, u16($1))))
}
policy systemFlags "restore system flags" (contents: 16) {
  T = not(zero(and(contents, u16($8000))))
  S = not(zero(and(contents, u16($2000))))
}
action writeCCR "write condition code register" (contents: 16) {
  apply conditionCode(contents)
}
action writeSR "write status register" (contents: 16) {
  perform writeCCR(contents)
  apply systemFlags(contents)
  INTERRUPTMASK <- truncate(shiftBits(contents, right, 8), 3)
}
```

## Data-register results

A byte or word write preserves the live upper part of its data register.
The three result policies set N from the size's sign bit, set Z for zero, and
clear V/C. They preserve X/T/S and also serve the remaining TypeScript families.

```cpu
operands dataRegisters {
  000 "D0" = register D0
  001 "D1" = register D1
  010 "D2" = register D2
  011 "D3" = register D3
  100 "D4" = register D4
  101 "D5" = register D5
  110 "D6" = register D6
  111 "D7" = register D7
}
policy byteResult "68000 result" (result: 8) {
  N = negative(result)
  Z = zero(result)
  V = 0
  C = 0
}
policy wordResult "68000 result" (result: 16) {
  N = negative(result)
  Z = zero(result)
  V = 0
  C = 0
}
policy longResult "68000 result" (result: 32) {
  N = negative(result)
  Z = zero(result)
  V = 0
  C = 0
}
```

## Register transfers

MOVE uses `00 zz ddd mmm sss rrr`: `zz=01` is byte, `10` long, `11` word.
The destination occupies `ddd/mmm`; the source `sss/rrr`. Mode `000` names Dn,
mode `001` An. Byte forms exclude address registers. Destination mode `001`
selects MOVEA, which sign-extends a word and preserves every flag.

Capture the source before selecting the destination. Write the destination before applying the result flags; preserve its live upper bits for a byte or word.

```cpu
family move8DataData "0001 ddd 000 000 rrr" for d in dataRegisters, r in dataRegisters named "MOVE.B {r},{d}" {
  originalSource = operand r
  result = truncate(originalSource, 8)
  preserved = operand d
  operand d <- or(and(preserved, u32($FFFFFF00)), extend(result, 32))
  apply byteResult(result)
}
```

Capture the source before selecting the destination. Write the destination before applying the result flags; preserve its live upper bits for a byte or word.

```cpu
family registerCopy "0011 ddd 000 000 rrr" for d in dataRegisters, r in dataRegisters named "MOVE.W {r},{d}" {
  originalSource = operand r
  result = truncate(originalSource, 16)
  preserved = operand d
  operand d <- or(and(preserved, u32($FFFF0000)), extend(result, 32))
  apply wordResult(result)
}
```

Capture the source before selecting the destination. Write the destination before applying the result flags; preserve its live upper bits for a byte or word.

```cpu
family move16AddressData "0011 ddd 000 001 rrr" for d in dataRegisters, r in addressRegisters named "MOVE.W {r},{d}" {
  sourceCode = operand r
  sourceRegister = source selectAddressRegister(sourceCode)
  originalSource = source readAddressRegister(sourceRegister)
  result = truncate(originalSource, 16)
  preserved = operand d
  operand d <- or(and(preserved, u32($FFFF0000)), extend(result, 32))
  apply wordResult(result)
}
```

Capture the source before selecting the destination. Replace the complete address register and preserve every flag.

```cpu
family move16DataAddress "0011 ddd 001 000 rrr" for d in addressRegisters, r in dataRegisters named "MOVEA.W {r},{d}" {

  result = truncate(originalSource, 16)
  destinationCode = operand d
  destinationRegister = source selectAddressRegister(destinationCode)
  perform writeAddressRegister(destinationRegister, signExtend(result, 32))
}
```

## Small constants, extension, and word exchange

MOVEQ encodes `0111 ddd 0 iiiiiiii`. Its signed eight-bit constant becomes a
complete long in Dn. The native operation-word decoder still passes the low byte
as an input; the chapter owns the encoding inventory and the body.

Sign-extend the immediate byte, replace Dn, then set N/Z and clear V/C.
Preserve X/T/S.

```cpu
family moveQuick (immediate: 8) "0111 ddd 0 xxxxxxxx" for d in dataRegisters named "MOVEQ #n,{d}" {
  result = signExtend(immediate, 32)
  operand d <- result
  apply longResult(result)
}
```

EXT occupies `0100 1000 1 s 000 rrr`, with `s=0` for byte-to-word and `s=1`
for word-to-long. EXT.W preserves the upper word from the same single read;
there is no live reread of Dn between calculation and writeback.

Read Dn once, sign-extend its byte to a word, preserve the captured upper word,
and write Dn before applying word-result flags.

```cpu
family extendWord "0100 1000 10 000 rrr" for r in dataRegisters named "EXT.W {r}" {
  original = operand r
  result = signExtend(truncate(original, 8), 16)
  operand r <- or(and(original, u32($FFFF0000)), extend(result, 32))
  apply wordResult(result)
}
```

Read Dn once, sign-extend its word to a long, and write Dn before applying
long-result flags.

```cpu
family extendLong "0100 1000 11 000 rrr" for r in dataRegisters named "EXT.L {r}" {
  original = operand r
  result = signExtend(truncate(original, 16), 32)
  operand r <- result
  apply longResult(result)
}
```

SWAP uses `0100 1000 01 000 rrr`, beside the EXT slots. Read Dn once and
exchange its high and low words. Apply long-result flags before writing Dn,
preserving the established execution order.

```cpu
family swap "0100 1000 01 000 rrr" for r in dataRegisters named "SWAP {r}" {
  original = operand r
  result = or(shiftBits(original, left, 16), shiftBits(original, right, 16))
  apply longResult(result)
  operand r <- result
}
```

## Register exchange

EXG uses `1100 ddd 1 ooooo rrr`. Operation `01000` exchanges Dn/Dn,
`01001` An/An, and `10001` Dn/An. Both identities must be selected before
either value is read, especially when A7 participates. Capture both originals,
write left then right, and preserve every flag, even for self-exchanges.

Resolve both register identities before reading either original. Capture both
values before writing left then right; preserve every flag.

```cpu
family exchangeDataData "1100 ddd 1 01000 rrr" for d in dataRegisters, r in dataRegisters named "EXG {d},{r}" {
  left = operand d
  right = operand r
  operand d <- right
  operand r <- left
}
```

Resolve both register identities before reading either original. Capture both
values before writing left then right; preserve every flag.

```cpu
family exchangeAddressAddress "1100 ddd 1 01001 rrr" for d in addressRegisters, r in addressRegisters named "EXG {d},{r}" {
  leftCode = operand d
  leftRegister = source selectAddressRegister(leftCode)
  rightCode = operand r
  rightRegister = source selectAddressRegister(rightCode)
  left = source readAddressRegister(leftRegister)
  right = source readAddressRegister(rightRegister)
  perform writeAddressRegister(leftRegister, right)
  perform writeAddressRegister(rightRegister, left)
}
```

Resolve both register identities before reading either original. Capture both
values before writing left then right; preserve every flag.

```cpu
family exchangeDataAddress "1100 ddd 1 10001 rrr" for d in dataRegisters, r in addressRegisters named "EXG {d},{r}" {
  rightCode = operand r
  rightRegister = source selectAddressRegister(rightCode)
  left = operand d
  right = source readAddressRegister(rightRegister)
  operand d <- right
  perform writeAddressRegister(rightRegister, left)
}
```

## Address-register indirect

Mode `010` means `(An)`: use the address register's contents without increment
or decrement. The three-bit code below is passed to the CPU's existing effective
address resolver. A7 resolves to SSP in supervisor mode or USP in user mode;
only the selected bank is read, at this operand's turn. The resolver uses the chapter-owned bank selection above.



The resolver returns a full 32-bit logical address. The memory connection
projects each access onto the 24-bit physical bus. Word accesses require an
even logical address; `lowBit(address)` detects an odd one before any byte at
that address is accessed. The fault returns to the CPU boundary for normal
address-error delivery. Thrown host errors and explicit bus errors retain the
same boundary handling as other instructions.

In the byte-access model, a word occupies a high byte followed by a low byte.
The expressions below retain logical addresses until the connection applies
physical projection. Address arithmetic wraps at 32 bits. A failed second
read leaves the destination and flags untouched; it cannot undo the first read.

Resolve the source and reject an odd address before reading its high then low
byte. After both reads, commit pending address updates and preserve the live
upper word of the destination. Write the complete result before setting N/Z
and clearing V/C. A failed read prevents writeback and flag changes.

```cpu
family load "0011 ddd 000 010 rrr" for d in dataRegisters, r in addressRegisters named "MOVE.W ({r}),{d}" {
  code = operand r
  address = resolve(16, u3(2), code)
  fault alignment read(address) if lowBit(address)
  high = memory(address)
  low = memory(add(address, u32(1)))
  result = concat(high, low)
  commit addresses
  preserved = operand d
  operand d <- or(and(preserved, u32($FFFF0000)), extend(result, 32))
  apply wordResult(result)
}
```

The destination mode `010` uses the same address-register codes. Stores
capture the source before resolving that destination and never read its old
memory contents. The address-update commit is explicit, as for other MOVE
forms, although plain `(An)` stages no updates. If the second write fails,
the first byte remains written and all flags retain their previous values.

Capture the source word before resolving the destination. Reject an odd
address before committing pending address updates or writing memory. Write
the high byte then the low byte, and only then set N/Z and clear V/C.
Never read destination memory; a failed write retains completed bytes and
preserves flags.

```cpu
family store "0011 ddd 010 000 rrr" for d in addressRegisters, r in dataRegisters named "MOVE.W {r},({d})" {
  originalSource = operand r
  result = truncate(originalSource, 16)
  code = operand d
  address = resolve(16, u3(2), code)
  fault alignment write(address) if lowBit(address)
  commit addresses
  memory(address) <- highByte(result)
  memory(add(address, u32(1))) <- lowByte(result)
  apply wordResult(result)
}
```

## Checks and remaining boundaries

The [register tests](../../../../tests/components/cpus/semantics/68000-registers.test.ts)
independently enumerate operation words and check widths, aliases, both stack
banks, live upper bits, and failure after every register/flag access. They also
cover every MOVEQ immediate byte and incoming flag combination. The
[chapter tests](../../../../tests/components/cpus/semantics/literate-68000.test.ts)
check schema and encoding ownership, indirect memory order, alignment faults,
physical projection, status packing/restoration, and formal edits that change
execution. Source and family inputs are captured numeric values; they are not
additional hardware registers.

The native core still decodes effective addresses and stages their auto-updates.
It also extracts MOVEQ's immediate byte, binds selected storage to native
register references, and owns fetching, retirement, reset, and exception entry.
Remaining TypeScript instruction builders preserve partial Dn writes and share
the chapter's flag policies and status actions. These are migration boundaries,
not absent CPU behavior. Cycle timing and later 680x0 extensions remain outside
the declared model.
