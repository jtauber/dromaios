# Motorola 6800

This chapter owns the 6800's stored state, packed condition codes, and all
197 documented instruction forms. Its `cpu` fences generate production
definitions, addressing, and opcode bindings. Execution boundaries still
come from TypeScript; the
[model contract](../../../../docs/cpus/6800/model.md) retains the public API,
reset, interrupt, waiting, and failure contracts during this migration.

The programmer has two independent byte accumulators, A and B, a sixteen-bit
index register X, a sixteen-bit stack pointer SP, and a sixteen-bit program
counter PC. A and B do not form the D register of later Motorola processors.
Memory holds 64 KiB, and words occupy two consecutive bytes, high byte first.
Addresses and values below use `$` for hexadecimal; `#` in an instruction name
marks an immediate value rather than a memory address.

The [Motorola programming and hardware references](../../../../docs/cpus/6800/model.md)
describe the hardware. Here the executable statements describe ordered
instruction effects, without cycles or dummy accesses. A failed memory access
prevents later effects while retaining earlier ones. Capturing a value makes
its timing explicit, including when a memory callback changes live state.

## Stored state

The complete declaration supplies the schema used by construction, snapshots,
machine parsing, generated instructions, and the execution runtime. It
preserves the existing public field names and their read order. Initial values
are supplied by the caller; storage declarations imply no reset defaults.

H records half-carry for decimal adjustment, I masks ordinary IRQ offers, N/Z
describe sign and zero, V records signed overflow, and C records carry or
borrow. The waiting latch records `WAI`; it is not a condition-code bit.

```cpu
cpu "6800"
state {
  register A: 8
  register B: 8
  register X: 16
  register SP: 16
  register PC: 16
  flag H
  flag I
  flag N
  flag Z
  flag V
  flag C
  latch WAITING = waiting
}
```

## Condition codes as a byte

The packed condition-code register is `11HINZVC`. Bits 7 and 6 read as one and
are ignored on restoration; they are not stored flags. The CC view captures
H/I/N/Z/V/C in that order, then assembles the byte. Restoration replaces the
complete flag object from a captured byte. The stack and interrupt
definitions below reuse this same view and policy, so TAP/TPA and saved frames agree.

```cpu
view CC "packed condition codes": 8 {
  h = flag H
  i = flag I
  n = flag N
  z = flag Z
  v = flag V
  c = flag C
  hi = or(select(h, u8($20), u8($00)), select(i, u8($10), u8($00)))
  nz = or(select(n, u8($08), u8($00)), select(z, u8($04), u8($00)))
  vc = or(select(v, u8($02), u8($00)), select(c, u8($01), u8($00)))
  return or(u8($C0), or(hi, or(nz, vc)))
}
policy CCFLAGS "restore condition codes" (status: 8) {
  H = not(zero(and(status, u8($20))))
  I = not(zero(and(status, u8($10))))
  N = not(zero(and(status, u8($08))))
  Z = not(zero(and(status, u8($04))))
  V = not(zero(and(status, u8($02))))
  C = not(zero(and(status, u8($01))))
}
```

Capture A and replace all six flags, ignoring bits 7/6. Preserve every register
and the waiting latch; no memory access occurs after the opcode fetch.

```cpu
family TAP "0000011 0" {
  status = register A
  replace CCFLAGS(status)
}
```

Capture all six flags and write A, setting reserved bits 7/6. Preserve the
flags and all other state; no memory access occurs after the opcode fetch.

```cpu
family TPA "0000011 1" {
  status = source CC
  A <- status
}
```

## Addressing and operand selection

The main byte families use `1 r mm oooo`: `r=0/1` selects A/B, `mm` selects
immediate/direct/indexed/extended in binary order, and `oooo` selects the
operation. An address source does not read the final data byte. This lets the
same mode serve a load, store, or comparison without inventing destination reads.

Direct addressing zero-extends one instruction byte to page zero. Indexed
addressing fetches an **unsigned** byte offset before reading live X, then adds
with sixteen-bit wrap. For example, X=`$FFF0`, offset=`$80` selects `$0070`.
Extended addressing fetches the high address byte before the low byte.

```cpu
source direct "direct, page zero": 16 {
  offset = fetch
  return extend(offset, 16)
}
source indexed "indexed by X with unsigned offset": 16 {
  offset = fetch
  index = register X
  return add(index, extend(offset, 16))
}
source extended "extended, high byte first": 16 {
  high = fetch
  low = fetch
  return concat(high, low)
}
source immediateByte "immediate byte": 8 {
  byte = fetch
  return byte
}
source immediateWord "immediate word, high byte first": 16 {
  high = fetch
  low = fetch
  return concat(high, low)
}
operands bytes {
  00 "#byte" = value immediateByte
  01 "direct" = memory direct
  10 "indexed" = memory indexed
  11 "extended" = memory extended
}
operands accumulators {
  0 "A" = register A
  1 "B" = register B
}
```

Word reads resolve their address once, then read high and low data bytes.
The second address wraps at `$FFFF`, including for indexed and extended words.
A direct word at `$00FF` continues at `$0100`; there is no page-zero wrap.
The word catalogue provides values, while `bytes.address` supplies the same
three memory addresses for word stores and omits the immediate selector.

```cpu
source directWord "direct word": 16 {
  address = source direct
  high = memory(address)
  low = memory(add(address, u16($0001)))
  return concat(high, low)
}
source indexedWord "indexed word": 16 {
  address = source indexed
  high = memory(address)
  low = memory(add(address, u16($0001)))
  return concat(high, low)
}
source extendedWord "extended word": 16 {
  address = source extended
  high = memory(address)
  low = memory(add(address, u16($0001)))
  return concat(high, low)
}
operands words {
  00 "#word" = value immediateWord
  01 "direct" = value directWord
  10 "indexed" = value indexedWord
  11 "extended" = value extendedWord
}
operands wordRegisters {
  0 "S" = register SP
  1 "X" = register X
}
```

## Loads, stores, and transfers

Loads, stores, transfers, and logic set N/Z from the captured result, clear V,
and preserve H/I/C. Byte and word policies differ only in result width. Flags
are explicit effects, not automatic consequences of a register write.

```cpu
policy NZV8 "6800 byte result" (result: 8) {
  N = negative(result)
  Z = zero(result)
  V = 0
}
policy NZV16 "6800 word result" (result: 16) {
  N = negative(result)
  Z = zero(result)
  V = 0
}
```

Fetch or read the complete byte before writing A/B, then set N/Z and clear V.
Preserve H/I/C and all other state. A failed read prevents register and flag
updates; completed instruction fetches remain.

```cpu
family LDA "1 r mm 0110" for r in accumulators, m in bytes.read named "LDA{r} {m}" {
  result = source m
  operand r <- result
  apply NZV8(result)
}
```

Resolve the address before capturing A/B. Do not read the destination; write
the captured byte once, even if unchanged. Only after a successful write, set
N/Z and clear V, preserving H/I/C. A failed write leaves flags unchanged;
completed fetches and addressing effects remain. There is no immediate store.

```cpu
family STA "1 r mm 0111" for r in accumulators, m in bytes.address named "STA{r} {m}" {
  address = source m
  result = operand r
  memory(address) <- result
  apply NZV8(result)
}
```

The word-transfer pattern is `1 r mm 111t`: here `r=0/1` selects SP/X, and
`t=0/1` selects load/store. For indexed LDX, the old X supplies the address;
only after both data reads succeed does the new word replace X.

Fetch or read the complete word high byte first, then write SP/X and set N/Z
from that captured word, clearing V. Preserve H/I/C and the waiting latch.
A failed read prevents register and flag updates.

```cpu
family LD "1 r mm 1110" for r in wordRegisters, m in words.read named "LD{r} {m}" {
  result = source m
  operand r <- result
  apply NZV16(result)
}
```

Resolve the address, then capture SP/X. Do not read the destination; write high
byte then low byte, wrapping at `$FFFF`, even if unchanged. Only after both writes
succeed, set N/Z and clear V, preserving H/I/C. A failed write leaves flags
unchanged; completed writes, fetches, and addressing effects remain.

```cpu
family ST "1 r mm 1111" for r in wordRegisters, m in bytes.address named "ST{r} {m}" {
  address = source m
  result = operand r
  memory(address) <- highByte(result)
  memory(add(address, u16($0001))) <- lowByte(result)
  apply NZV16(result)
}
```

Transfers use `0001011 d`, with `d=0` selecting A to B and `d=1` B to A.

Capture A and write B, then set N/Z from that byte and clear V. Preserve H/I/C
and all other state. No data-memory access occurs.

```cpu
family TAB "0001011 0" {
  result = register A
  B <- result
  apply NZV8(result)
}
```

Capture B and write A, then set N/Z from that byte and clear V. Preserve H/I/C
and all other state. No data-memory access occurs.

```cpu
family TBA "0001011 1" {
  result = register B
  A <- result
  apply NZV8(result)
}
```

## Logic

In `1 r mm oooo`, operation values `0100/0101/1000/1010` select AND/BIT/EOR/ORA.
The original mnemonics ORAA/ORAB contain the operation name ORA followed by the
accumulator letter. BIT tests the AND result without replacing the accumulator;
its flags describe that result, not individual bits copied from memory.

Fetch or read the operand before capturing A/B. Combine the captured bytes by
AND, write the result, then set N/Z and clear V. Preserve H/I/C. A failed read
prevents register and flag updates.

```cpu
family AND "1 r mm 0100" for r in accumulators, m in bytes.read named "AND{r} {m}" {
  right = source m
  accumulator = operand r
  result = and(accumulator, right)
  operand r <- result
  apply NZV8(result)
}
```

Fetch or read the operand before capturing A/B. Test their AND result without
writing either operand. Set N/Z and clear V, preserving H/I/C. A failed read
prevents flag updates.

```cpu
family BIT "1 r mm 0101" for r in accumulators, m in bytes.read named "BIT{r} {m}" {
  right = source m
  accumulator = operand r
  result = and(accumulator, right)
  apply NZV8(result)
}
```

Fetch or read the operand before capturing A/B. Combine the captured bytes by
exclusive OR, write the result, then set N/Z and clear V. Preserve H/I/C. A
failed read prevents register and flag updates.

```cpu
family EOR "1 r mm 1000" for r in accumulators, m in bytes.read named "EOR{r} {m}" {
  right = source m
  accumulator = operand r
  result = xor(accumulator, right)
  operand r <- result
  apply NZV8(result)
}
```

Fetch or read the operand before capturing A/B. Combine the captured bytes by
inclusive OR, write the result, then set N/Z and clear V. Preserve H/I/C. A
failed read prevents register and flag updates.


## Comparisons

Byte comparisons subtract without storing the result. C means **borrow**, N/Z
describe the wrapped byte, and V reports signed subtraction overflow. Incoming
C is ignored; H/I are preserved. The pattern `1 r mm 0001` selects CMPA/CMPB.

```cpu
policy COMPARE8 "6800 byte comparison" (left: 8, right: 8, result: 8) {
  N = negative(result)
  Z = zero(result)
  V = overflow(left, right)
  C = borrow(left, right)
}
```

Fetch or read the source before capturing A/B. Subtract it, set N/Z/V/C, and
preserve H/I. Do not write a result. A failed read leaves flags unchanged;
completed fetches and addressing effects remain.

```cpu
family CMP "1 r mm 0001" for r in accumulators, m in bytes.read named "CMP{r} {m}" {
  right = source m
  left = operand r
  result = subtract(left, right)
  apply COMPARE8(left, right, result)
}
```

Compare A with B without writing either register. Capture B before A, ignore
incoming C, and set N/Z/V/C from byte subtraction, preserving H/I. No data-memory
access occurs.

```cpu
family CBA "0001000 1" {
  right = register B
  left = register A
  result = subtract(left, right)
  apply COMPARE8(left, right, result)
}
```

The original 6800's CPX (`10 mm 1100`) is not a full sixteen-bit signed compare.
Z tests the whole word, but N/V describe high-byte subtraction **without** the
low-byte borrow. C is preserved. For X=`$1200`, operand=`$1201`, the word result
is `$FFFF` but the high-byte result is `$00`: N/V/Z are all clear. The
[model's CPX notes](../../../../docs/cpus/6800/model.md#subtraction-and-comparison) explain this
distinction from later-family processors.

```cpu
policy COMPAREX "6800 CPX high-byte N/V and whole-word Z" (left: 16, right: 16, result: 16) {
  N = negative(subtract(highByte(left), highByte(right)))
  Z = zero(result)
  V = overflow(highByte(left), highByte(right))
}
```

Fetch or read the complete high-first word before capturing X. N/V describe
high-byte subtraction without low-byte borrow; Z tests whole-word equality.
Preserve H/I/C and X. A failed read leaves flags unchanged; completed fetches
and addressing effects remain.

```cpu
family CPX "10 mm 1100" for m in words.read {
  right = source m
  left = register X
  result = subtract(left, right)
  apply COMPAREX(left, right, result)
}
```

## Arithmetic and decimal adjustment

The arithmetic selectors in `1 r mm oooo` are `0000` SUB, `0010` SBC,
`1001` ADC, and `1011` ADD. Read the complete operand before the selected
accumulator. ADC/SBC then read C as incoming carry/borrow. Flags change before
accumulator writeback, unlike loads and logic. All operations preserve I;
subtraction preserves H, while addition updates it from the low-nibble carry.

```cpu
policy ADD8 "6800 addition" (left: 8, right: 8, result: 8, incoming: flag) {
  N = negative(result)
  Z = zero(result)
  V = addOverflow(left, right, incoming)
  C = carry(left, right, incoming)
  H = halfCarry(left, right, incoming)
}
policy SUB8 "6800 subtraction" (left: 8, right: 8, result: 8, incoming: flag) {
  N = negative(result)
  Z = zero(result)
  V = overflow(left, right, incoming)
  C = borrow(left, right, incoming)
}
```

Fetch or read the operand, then A/B; ignore incoming C. Add with byte wrap,
set N/Z/V/C/H, and write A/B after flags. Preserve I and other state. A failed
source read prevents arithmetic, flags, and writeback.

```cpu
family ADD "1 r mm 1011" for r in accumulators, m in bytes.read named "ADD{r} {m}" {
  right = source m
  left = operand r
  result = add(left, right)
  apply ADD8(left, right, result, 0)
  operand r <- result
}
```

Fetch or read the operand, then A/B, then incoming C. Add all three, set
N/Z/V/C/H, and write A/B after flags. Preserve I and other state; failed reads
prevent later effects.

```cpu
family ADC "1 r mm 1001" for r in accumulators, m in bytes.read named "ADC{r} {m}" {
  right = source m
  left = operand r
  carry = flag C
  result = add(left, right, carry)
  apply ADD8(left, right, result, carry)
  operand r <- result
}
```

Fetch or read the operand, then A/B; ignore incoming C. Subtract with byte wrap,
set N/Z/V/C with C meaning borrow, and write A/B after flags. Preserve H/I and
other state; failed reads prevent later effects.

```cpu
family SUB "1 r mm 0000" for r in accumulators, m in bytes.read named "SUB{r} {m}" {
  right = source m
  left = operand r
  result = subtract(left, right)
  apply SUB8(left, right, result, 0)
  operand r <- result
}
```

Fetch or read the operand, then A/B, then incoming C as borrow. Subtract the
operand and borrow, set N/Z/V/C, and write A/B after flags. Preserve H/I and
other state; failed reads prevent later effects.

```cpu
family SBC "1 r mm 0010" for r in accumulators, m in bytes.read named "SBC{r} {m}" {
  right = source m
  left = operand r
  carry = flag C
  result = subtract(left, right, carry)
  apply SUB8(left, right, result, carry)
  operand r <- result
}
```

ABA and SBA use B directly, with no operand bytes. Unlike the memory/immediate
families, their declared capture order is A then B. CBA, defined earlier,
compares without writeback and retains its B-before-A capture order.

Read A then B and add, ignoring incoming C. Update N/Z/V/C/H before writing A;
preserve B, I, and every other register. No data-memory access occurs.

```cpu
family ABA "0001 1011" {
  left = register A
  right = register B
  result = add(left, right)
  apply ADD8(left, right, result, 0)
  A <- result
}
```

Read A then B and subtract, ignoring incoming C. Update N/Z/V/C before writing
A; preserve B, H/I, and every other register. No data-memory access occurs.

```cpu
family SBA "0001 0000" {
  left = register A
  right = register B
  result = subtract(left, right)
  apply SUB8(left, right, result, 0)
  A <- result
}
```

DAA corrects a packed-decimal addition in A. Select `$06` when the low nibble
exceeds nine or H is set, and `$60` when the original byte exceeds `$99` or C
is set. Both choices use the **original** A. The model defines this calculation
for invalid decimal digits too; its [DAA contract](../../../../docs/cpus/6800/model.md#decimal-adjustment)
clears the hardware's undefined V. H and I remain unchanged.

```cpu
policy DECIMAL "6800 DAA" (original: 8, correction: 8, result: 8, incoming: flag) {
  N = negative(result)
  Z = zero(result)
  V = 0
  C = or(incoming, carry(original, correction))
}
```

Capture A, H, then C; choose both corrections from those captures. Add them to
A with byte wrap. Set N/Z, clear V, and retain or set C before writing A.
Preserve H/I and other state. No instruction or data-memory access occurs.

```cpu
family DAA "0001 1001" {
  original = register A
  half = flag H
  carry = flag C
  low = select(or(not(borrow(and(original, u8($0F)), u8($0A))), half), u8($06), u8($00))
  high = select(or(not(borrow(original, u8($9A))), carry), u8($60), u8($00))
  correction = or(low, high)
  result = add(original, correction)
  apply DECIMAL(original, correction, result, carry)
  A <- result
}
```

## Unary byte operations

Unary instructions use `01 tt oooo`: `tt=00/01` selects A/B, while `tt=10/11`
selects indexed/extended memory. `oooo` selects NEG=`0000`, COM=`0011`,
LSR=`0100`, ROR=`0110`, ASR=`0111`, ASL=`1000`, ROL=`1001`, DEC=`1010`,
INC=`1100`, TST=`1101`, or CLR=`1111`. JMP=`1110` uses only the memory
address and is defined with control flow below. Other selectors remain undefined.

Register and memory forms share their flag policies. Memory forms capture one
address for both read and write, so an operand callback changing X cannot move
the destination. Flags change before writeback. TST never writes; the original
6800 CLR never reads the destination. These distinctions differ from the 6809.

```cpu
operands unaryMemory {
  0 "indexed" = memory indexed
  1 "extended" = memory extended
}
policy NEGFLAGS "6800 NEG" (original: 8, result: 8) {
  N = negative(result)
  Z = zero(result)
  V = overflow(u8($00), original)
  C = borrow(u8($00), original)
}
policy COMFLAGS "6800 COM" (result: 8) {
  N = negative(result)
  Z = zero(result)
  V = 0
  C = 1
}
policy SHIFTFLAGS "6800 shift" (result: 8, outgoing: flag) {
  N = negative(result)
  Z = zero(result)
  C = outgoing
  V = xor(negative(result), outgoing)
}
policy DECFLAGS "6800 DEC" (original: 8, result: 8) {
  N = negative(result)
  Z = zero(result)
  V = zero(subtract(original, u8($80)))
}
policy INCFLAGS "6800 INC" (original: 8, result: 8) {
  N = negative(result)
  Z = zero(result)
  V = zero(subtract(original, u8($7F)))
}
policy TESTFLAGS "6800 TST" (result: 8) {
  N = negative(result)
  Z = zero(result)
  V = 0
  C = 0
}
policy CLEARFLAGS "6800 CLR" () {
  N = 0
  Z = 1
  C = 0
  V = 0
}
```

### NEG

Negate modulo 256. V marks original `$80`; C marks a nonzero original. Set N/Z from the result; preserve H/I.
No register other than the selected destination changes.

```cpu
family NEGregister "010 r 0000" for r in accumulators named "NEG{r}" {
  original = operand r
  result = subtract(u8($00), original)
  apply NEGFLAGS(original, result)
  operand r <- result
}
```

Resolve the address once. Negate modulo 256. V marks original `$80`; C marks a nonzero original. Set N/Z from the result; preserve H/I.
Apply flags before any write; a failed write retains them and completed addressing effects.

```cpu
family NEGmemory "011 m 0000" for m in unaryMemory.address named "NEG {m}" {
  address = source m
  original = memory(address)
  result = subtract(u8($00), original)
  apply NEGFLAGS(original, result)
  memory(address) <- result
}
```

## Branches and jumps

Short branches use `0010 ttt p`: `ttt` selects always/HI/CC/NE/VC/PL/GE/GT,
and `p` inverts the test. `$20` is BRA; `$21` is undefined on the original 6800,
which has no BRN. The signed byte displacement is added to PC **after** its
fetch. Conditional branches read their flags after fetching, and access PC
only if taken. No flags change.

with word wrapping. Preserve all flags and other registers.

## The descending stack

SP names the next free byte. A push writes at SP and only then decrements the
**live** SP. A pull increments live SP before reading at the resulting live
address. Each step wraps at sixteen bits. A memory callback may change SP;
the next declared read observes that change. Failed pushes retain earlier
writes and decrements; failed pulls retain their preceding increments.

A `perform` expands an earlier action with its own captures. Arguments are
captured before the action begins, and no local name leaks back to its caller.
This lets all stacks share the explicit byte-transfer rule. Sources return
values; actions perform effects.

```cpu
action pushByte "push byte through SP" (byte: 8) using memory {
  address = register SP
  memory(address) <- byte
  pointer = register SP
  SP <- subtract(pointer, u16($0001))
}
action pushWord "push high-first word through SP" (word: 16) using memory {
  perform pushByte(lowByte(word))
  perform pushByte(highByte(word))
}
source popByte "pop byte through SP": 8 {
  pointer = register SP
  SP <- add(pointer, u16($0001))
  address = register SP
  byte = memory(address)
  return byte
}
source popWord "pop high-first word through SP": 16 {
  high = source popByte
  low = source popByte
  return concat(high, low)
}
```

Words reside high byte first at ascending addresses. A descending stack must
therefore push low then high; pulls read high then low. TSX copies SP+1 into X,
pointing at the top occupied byte; TXS sets SP to X-1, restoring the free-byte
convention. These adjustments were defined above without memory accesses.

Capture A/B before reading SP, then push that byte. Decrement live SP only after
the write succeeds. Preserve all flags and every other register.

```cpu
family PSH "0011 011 r" for r in accumulators named "PSH{r}" {
  original = operand r
  perform pushByte(original)
}
```


### Calls and returns

BSR is `$8D`; JSR uses `$AD/$BD` for indexed/extended targets. `$9D` is undefined:
the original chip has no direct JSR. Resolve the complete target first, capture
the current PC as the return address, push low/high, and only then write PC.
The target remains captured even if stack writes overlap the instruction bytes.

```cpu
source relativeTarget "relative call target": 16 {
  offset = fetch
  pc = register PC
  return add(pc, signExtend(offset, 16))
}
action call "save return address and call" (target: 16) using memory {
  returnPC = register PC
  perform pushWord(returnPC)
  PC <- target
}
```

PC again for the return address, push it low/high, and write the target only after
both writes succeed. Preserve all flags and other registers.

```cpu

  target = source relativeTarget
  perform call(target)
}
```

### Interrupt frames, WAI, SWI, and RTI

The saved frame contains PC, X, A, B, and CC in push order. Capture each field
only when its turn arrives. Word pushes transfer low/high, and CC is captured
last, with the **old** I flag. The action below serves WAI, SWI, and external
entry. Frame saving itself neither masks interrupts nor changes waiting state.

```cpu
action saveFrame "save the complete interrupt frame" using memory {
  pc = register PC
  perform pushWord(pc)
  index = register X
  perform pushWord(index)
  a = register A
  perform pushByte(a)
  b = register B
  perform pushByte(b)
  status = source CC
  perform pushByte(status)
}
```

External entry and SWI skip frame saving when WAI already saved it. After any
required frame, release waiting, set I, and read both vector bytes high first
before changing PC. A failed vector read retains those state and stack effects.

```cpu
action enterInterrupt "external interrupt entry" (vector: 16) using memory {
  waiting = latch WAITING
  when not(waiting) {
    perform saveFrame()
  }
  WAITING <- 0
  apply IFLAG(1)
  high = memory(vector)
  low = memory(add(vector, u16($0001)))
  PC <- concat(high, low)
}
```

`0011111 s` selects WAI=`s=0` or SWI=`s=1`. WAI saves the frame before waiting;
SWI enters the software vector at `$FFFA`. The core still decides when IRQ/NMI
requests are recognized and when a waiting CPU can execute again.

Save the complete frame, then set WAITING. Preserve I until wake-up. Failed
stack writes prevent waiting and retain only completed frame bytes and SP changes.

```cpu
family WAI "0011111 0" {
  perform saveFrame()
  WAITING <- 1
}
```

Save a frame unless WAI already supplied it, release waiting, set I, then read
the high-first `$FFFA` vector before replacing PC. Preserve H/N/Z/V/C and other
registers; failed accesses retain completed effects.

```cpu
family SWI "0011111 1" {
  perform enterInterrupt(u16($FFFA))
}
```

RTI pulls CC, B, A, X, and PC in that order. Replace all six flags immediately
after CC is read; commit each later register only after its complete read.
Preserve waiting. Each pull increments live SP before reading; a failed read
retains earlier increments and restorations.

```cpu
family RTI "0011 1011" {
  status = source popByte
  replace CCFLAGS(status)
  b = source popByte
  B <- b
  a = source popByte
  A <- a
  index = source popWord
  X <- index
  pc = source popWord
  PC <- pc
}
```
