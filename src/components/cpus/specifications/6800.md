# Motorola 6800

This chapter owns the 6800's stored state, packed condition codes, and the
load, store, transfer, logic, and comparison instruction families. Its `cpu`
fences generate production definitions and opcode bindings. The remaining
instructions and execution boundaries still come from TypeScript; the
[model contract](../../../../docs/cpus/6800/model.md) retains the public API,
reset, interrupt, waiting, and failure contracts during this migration.

The programmer has two independent byte accumulators, A and B, a sixteen-bit
index register X, a sixteen-bit stack pointer SP, and a sixteen-bit program
counter PC. A and B do not form the D register of later Motorola processors.
Memory holds 64 KiB, and words occupy two consecutive bytes, high byte first.
Addresses and values below use `$` for hexadecimal; `#` in an instruction name
marks an immediate value rather than a memory address.

The [Motorola programming and hardware references](../../../../docs/cpus/6800/model.md)
describe the hardware. Here the executable statements describe ordered
instruction effects, without cycles or dummy accesses. A failed memory access
prevents later effects while retaining earlier ones. Capturing a value makes
its timing explicit, including when a memory callback changes live state.

## Stored state

The complete declaration supplies the schema used by construction, snapshots,
machine parsing, and both chapter and remaining TypeScript instructions. It
preserves the existing public field names and their read order. Initial values
are supplied by the caller; storage declarations imply no reset defaults.

H records half-carry for decimal adjustment, I masks ordinary IRQ offers, N/Z
describe sign and zero, V records signed overflow, and C records carry or
borrow. The waiting latch records `WAI`; it is not a condition-code bit.

```cpu
cpu "6800"
state {
  register A: 8
  register B: 8
  register X: 16
  register SP: 16
  register PC: 16
  flag H
  flag I
  flag N
  flag Z
  flag V
  flag C
  latch WAITING = waiting
}
```

## Condition codes as a byte

The packed condition-code register is `11HINZVC`. Bits 7 and 6 read as one and
are ignored on restoration; they are not stored flags. The CC view captures
H/I/N/Z/V/C in that order, then assembles the byte. Restoration replaces the
complete flag object from a captured byte. The remaining stack and interrupt
definitions reuse this same view and policy, so TAP/TPA and saved frames agree.

```cpu
view CC "packed condition codes": 8 {
  h = flag H
  i = flag I
  n = flag N
  z = flag Z
  v = flag V
  c = flag C
  hi = or(select(h, u8($20), u8($00)), select(i, u8($10), u8($00)))
  nz = or(select(n, u8($08), u8($00)), select(z, u8($04), u8($00)))
  vc = or(select(v, u8($02), u8($00)), select(c, u8($01), u8($00)))
  return or(u8($C0), or(hi, or(nz, vc)))
}
policy CCFLAGS "restore condition codes" (status: 8) {
  H = not(zero(and(status, u8($20))))
  I = not(zero(and(status, u8($10))))
  N = not(zero(and(status, u8($08))))
  Z = not(zero(and(status, u8($04))))
  V = not(zero(and(status, u8($02))))
  C = not(zero(and(status, u8($01))))
}
```

Capture A and replace all six flags, ignoring bits 7/6. Preserve every register
and the waiting latch; no memory access occurs after the opcode fetch.

```cpu
family TAP "0000011 0" {
  status = register A
  replace CCFLAGS(status)
}
```

Capture all six flags and write A, setting reserved bits 7/6. Preserve the
flags and all other state; no memory access occurs after the opcode fetch.

```cpu
family TPA "0000011 1" {
  status = source CC
  A <- status
}
```

## Addressing and operand selection

The main byte families use `1 r mm oooo`: `r=0/1` selects A/B, `mm` selects
immediate/direct/indexed/extended in binary order, and `oooo` selects the
operation. An address source does not read the final data byte. This lets the
same mode serve a load, store, or comparison without inventing destination reads.

Direct addressing zero-extends one instruction byte to page zero. Indexed
addressing fetches an **unsigned** byte offset before reading live X, then adds
with sixteen-bit wrap. For example, X=`$FFF0`, offset=`$80` selects `$0070`.
Extended addressing fetches the high address byte before the low byte.

```cpu
source direct "direct, page zero": 16 {
  offset = fetch
  return extend(offset, 16)
}
source indexed "indexed by X with unsigned offset": 16 {
  offset = fetch
  index = register X
  return add(index, extend(offset, 16))
}
source extended "extended, high byte first": 16 {
  high = fetch
  low = fetch
  return concat(high, low)
}
source immediateByte "immediate byte": 8 {
  byte = fetch
  return byte
}
source immediateWord "immediate word, high byte first": 16 {
  high = fetch
  low = fetch
  return concat(high, low)
}
operands bytes {
  00 "#byte" = value immediateByte
  01 "direct" = memory direct
  10 "indexed" = memory indexed
  11 "extended" = memory extended
}
operands accumulators {
  0 "A" = register A
  1 "B" = register B
}
```

Word reads resolve their address once, then read high and low data bytes.
The second address wraps at `$FFFF`, including for indexed and extended words.
A direct word at `$00FF` continues at `$0100`; there is no page-zero wrap.
The word catalogue provides values, while `bytes.address` supplies the same
three memory addresses for word stores and omits the immediate selector.

```cpu
source directWord "direct word": 16 {
  address = source direct
  high = memory(address)
  low = memory(add(address, u16($0001)))
  return concat(high, low)
}
source indexedWord "indexed word": 16 {
  address = source indexed
  high = memory(address)
  low = memory(add(address, u16($0001)))
  return concat(high, low)
}
source extendedWord "extended word": 16 {
  address = source extended
  high = memory(address)
  low = memory(add(address, u16($0001)))
  return concat(high, low)
}
operands words {
  00 "#word" = value immediateWord
  01 "direct" = value directWord
  10 "indexed" = value indexedWord
  11 "extended" = value extendedWord
}
operands wordRegisters {
  0 "S" = register SP
  1 "X" = register X
}
```

## Loads, stores, and transfers

Loads, stores, transfers, and logic set N/Z from the captured result, clear V,
and preserve H/I/C. Byte and word policies differ only in result width. Flags
are explicit effects, not automatic consequences of a register write.

```cpu
policy NZV8 "6800 byte result" (result: 8) {
  N = negative(result)
  Z = zero(result)
  V = 0
}
policy NZV16 "6800 word result" (result: 16) {
  N = negative(result)
  Z = zero(result)
  V = 0
}
```

Fetch or read the complete byte before writing A/B, then set N/Z and clear V.
Preserve H/I/C and all other state. A failed read prevents register and flag
updates; completed instruction fetches remain.

```cpu
family LDA "1 r mm 0110" for r in accumulators, m in bytes.read named "LDA{r} {m}" {
  result = source m
  operand r <- result
  apply NZV8(result)
}
```

Resolve the address before capturing A/B. Do not read the destination; write
the captured byte once, even if unchanged. Only after a successful write, set
N/Z and clear V, preserving H/I/C. A failed write leaves flags unchanged;
completed fetches and addressing effects remain. There is no immediate store.

```cpu
family STA "1 r mm 0111" for r in accumulators, m in bytes.address named "STA{r} {m}" {
  address = source m
  result = operand r
  memory(address) <- result
  apply NZV8(result)
}
```

The word-transfer pattern is `1 r mm 111t`: here `r=0/1` selects SP/X, and
`t=0/1` selects load/store. For indexed LDX, the old X supplies the address;
only after both data reads succeed does the new word replace X.

Fetch or read the complete word high byte first, then write SP/X and set N/Z
from that captured word, clearing V. Preserve H/I/C and the waiting latch.
A failed read prevents register and flag updates.

```cpu
family LD "1 r mm 1110" for r in wordRegisters, m in words.read named "LD{r} {m}" {
  result = source m
  operand r <- result
  apply NZV16(result)
}
```

Resolve the address, then capture SP/X. Do not read the destination; write high
byte then low byte, wrapping at `$FFFF`, even if unchanged. Only after both writes
succeed, set N/Z and clear V, preserving H/I/C. A failed write leaves flags
unchanged; completed writes, fetches, and addressing effects remain.

```cpu
family ST "1 r mm 1111" for r in wordRegisters, m in bytes.address named "ST{r} {m}" {
  address = source m
  result = operand r
  memory(address) <- highByte(result)
  memory(add(address, u16($0001))) <- lowByte(result)
  apply NZV16(result)
}
```

Transfers use `0001011 d`, with `d=0` selecting A to B and `d=1` B to A.

Capture A and write B, then set N/Z from that byte and clear V. Preserve H/I/C
and all other state. No data-memory access occurs.

```cpu
family TAB "0001011 0" {
  result = register A
  B <- result
  apply NZV8(result)
}
```

Capture B and write A, then set N/Z from that byte and clear V. Preserve H/I/C
and all other state. No data-memory access occurs.

```cpu
family TBA "0001011 1" {
  result = register B
  A <- result
  apply NZV8(result)
}
```

## Logic

In `1 r mm oooo`, operation values `0100/0101/1000/1010` select AND/BIT/EOR/ORA.
The original mnemonics ORAA/ORAB contain the operation name ORA followed by the
accumulator letter. BIT tests the AND result without replacing the accumulator;
its flags describe that result, not individual bits copied from memory.

Fetch or read the operand before capturing A/B. Combine the captured bytes by
AND, write the result, then set N/Z and clear V. Preserve H/I/C. A failed read
prevents register and flag updates.

```cpu
family AND "1 r mm 0100" for r in accumulators, m in bytes.read named "AND{r} {m}" {
  right = source m
  accumulator = operand r
  result = and(accumulator, right)
  operand r <- result
  apply NZV8(result)
}
```

Fetch or read the operand before capturing A/B. Test their AND result without
writing either operand. Set N/Z and clear V, preserving H/I/C. A failed read
prevents flag updates.

```cpu
family BIT "1 r mm 0101" for r in accumulators, m in bytes.read named "BIT{r} {m}" {
  right = source m
  accumulator = operand r
  result = and(accumulator, right)
  apply NZV8(result)
}
```

Fetch or read the operand before capturing A/B. Combine the captured bytes by
exclusive OR, write the result, then set N/Z and clear V. Preserve H/I/C. A
failed read prevents register and flag updates.

```cpu
family EOR "1 r mm 1000" for r in accumulators, m in bytes.read named "EOR{r} {m}" {
  right = source m
  accumulator = operand r
  result = xor(accumulator, right)
  operand r <- result
  apply NZV8(result)
}
```

Fetch or read the operand before capturing A/B. Combine the captured bytes by
inclusive OR, write the result, then set N/Z and clear V. Preserve H/I/C. A
failed read prevents register and flag updates.

```cpu
family ORA "1 r mm 1010" for r in accumulators, m in bytes.read named "ORA{r} {m}" {
  right = source m
  accumulator = operand r
  result = or(accumulator, right)
  operand r <- result
  apply NZV8(result)
}
```

## Comparisons

Byte comparisons subtract without storing the result. C means **borrow**, N/Z
describe the wrapped byte, and V reports signed subtraction overflow. Incoming
C is ignored; H/I are preserved. The pattern `1 r mm 0001` selects CMPA/CMPB.

```cpu
policy COMPARE8 "6800 byte comparison" (left: 8, right: 8, result: 8) {
  N = negative(result)
  Z = zero(result)
  V = overflow(left, right)
  C = borrow(left, right)
}
```

Fetch or read the source before capturing A/B. Subtract it, set N/Z/V/C, and
preserve H/I. Do not write a result. A failed read leaves flags unchanged;
completed fetches and addressing effects remain.

```cpu
family CMP "1 r mm 0001" for r in accumulators, m in bytes.read named "CMP{r} {m}" {
  right = source m
  left = operand r
  result = subtract(left, right)
  apply COMPARE8(left, right, result)
}
```

Compare A with B without writing either register. Capture B before A, ignore
incoming C, and set N/Z/V/C from byte subtraction, preserving H/I. No data-memory
access occurs.

```cpu
family CBA "0001000 1" {
  right = register B
  left = register A
  result = subtract(left, right)
  apply COMPARE8(left, right, result)
}
```

The original 6800's CPX (`10 mm 1100`) is not a full sixteen-bit signed compare.
Z tests the whole word, but N/V describe high-byte subtraction **without** the
low-byte borrow. C is preserved. For X=`$1200`, operand=`$1201`, the word result
is `$FFFF` but the high-byte result is `$00`: N/V/Z are all clear. The
[model's CPX notes](../../../../docs/cpus/6800/model.md#subtraction-and-comparison) explain this
distinction from later-family processors.

```cpu
policy COMPAREX "6800 CPX high-byte N/V and whole-word Z" (left: 16, right: 16, result: 16) {
  N = negative(subtract(highByte(left), highByte(right)))
  Z = zero(result)
  V = overflow(highByte(left), highByte(right))
}
```

Fetch or read the complete high-first word before capturing X. N/V describe
high-byte subtraction without low-byte borrow; Z tests whole-word equality.
Preserve H/I/C and X. A failed read leaves flags unchanged; completed fetches
and addressing effects remain.

```cpu
family CPX "10 mm 1100" for m in words.read {
  right = source m
  left = register X
  result = subtract(left, right)
  apply COMPAREX(left, right, result)
}
```
